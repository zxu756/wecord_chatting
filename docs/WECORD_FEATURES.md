# WeCord 功能全览

> 截至 2026-10-20（主分支 `wecord-foundation`）。本文列出项目里**已经实现并上线**的全部功能，按领域分组，每项写明用户能做什么、关键规则和实现位置，方便规划下一步。
> 「上线」指已部署到网页（https://wecord.jokebear.fyi）、已安装到 iPhone、已编译 macOS 版，数据库改动已推到 Supabase 线上项目。

---

## 0. 项目概况

| 项目 | 内容 |
|---|---|
| 产品定位 | 微信式的私聊/群聊 + Discord 式的「圈子」社区 + Slack 式的协作工具（笔记、任务、接龙），统一在一个应用里 |
| 平台 | Web（Cloudflare Worker 托管，可安装为 PWA）、iOS（iPhone 和 iPad，真机 release 安装）、macOS（release 构建） |
| 客户端 | Flutter + Riverpod 3 + go_router；约 607 个 Dart 文件、17.5 万行 |
| 后端 | Supabase（Postgres + RLS + Realtime + Storage + Edge Functions + pg_cron + pg_net + Vault），项目 `zpfternchrwboweellka` |
| 数据库 | 147 个迁移（`supabase/migrations/`），几乎所有业务规则都在 SQL（RLS + security definer 函数）里强制执行 |
| Edge Functions | 17 个：`ai`、`bot-api`、`bots`、`chat-event-reminders`、`data-export`、`delete-account`、`expire-messages`、`expire-stories`、`gif-search`、`link-preview`、`livekit-token`、`office-preview`、`push`、`scheduled-dispatch`、`sessions`、`sound-upload`、`webhook` |
| 外部服务 | LiveKit Cloud（语音/视频）、Gotenberg on Google Cloud Run（Office→PDF 预览）、GIPHY（GIF 搜索）、OpenCode Go（AI，OpenAI 兼容接口，可切换）、OpenStreetMap/Nominatim/Overpass（地图，可配置）、Krisp（降噪，LiveKit 插件） |
| 测试 | 278 个测试文件、约 3822 个测试（单元 + 组件 + 无障碍守卫 + SQL 行为脚本 + Deno 测试），上线前全量通过 |
| 语言 | 中文（简体）+ 英文；`tr()` 翻译体系，覆盖率测试保证不漏翻 |
| 设计 | 「设计语言 C」：暖纸色、玻璃浮层、圆角方形（squircle），见 `docs/design/wecord-design-language.md` |
| 仓库 | https://github.com/zxu756/wecord_chatting.git |

## 1. 账号与身份

- **注册 / 登录**：邮箱 + 密码，注册时选用户名和显示名；首次登录自动创建资料（profile bootstrap）。
- **找回密码**：邮件链接 → 设置新密码页面（`/reset-password`）。
- **两步验证（TOTP）**：设置里开启，用身份验证器 App 扫码绑定；登录时要求输入 6 位验证码；关闭需要验证码。
- **退出登录**：退出当前设备；会先停止实时位置共享、注销推送。
- **设备管理**（设置 → 隐私与安全 → 设备）：列出所有登录中的会话（设备名、平台、应用版本、最近活跃），可单独登出某台设备或「登出其他所有设备」；不显示 IP 和位置。
- **新登录提醒**：新设备首次登记时（`user_devices` 新增一行，令牌刷新不算；首次登录不提醒），其他设备收到推送（按订阅的语言和时区），通知页「安全」芯片出现卡片（设备名、平台、时间，不含 IP 和位置）；「是我本人」关闭提醒，「不是我」通过 `sessions` 函数登出那台设备并引导修改密码。
- **删除账号**：二次确认后永久删除；连带清理头像、横幅、聊天背景照片、朋友圈图片/视频、日常的照片/视频等存储文件。
- **导出我的数据**：一键生成 ZIP（index.html + 各分区页面 + `data/*.json`），带真实进度条；内容包括资料、好友、自己发的消息、朋友圈（含自己的照片/视频）、还在展示的日常（文件给下载链接）和密友名单、好友标签和星标、接龙、笔记、任务清单、收藏、提醒、定时消息、聊天背景。只导出自己写的内容，绝不包含别人的私有内容。24 小时限一次，过期文件自动清理。
- **个人资料**：头像、横幅、显示名、用户名、简介、代词、自定义状态（emoji + 文字 + 过期时间）；头像/横幅上传前自动压缩（512px / 1600px）并去掉 GPS 等元数据，动图头像原样保留。
- **资料可见范围**：简介、横幅、代词可设为所有人 / 好友 / 仅自己等；服务器在所有读取路径强制执行（含聊天成员列表、置顶、回应列表、投票名单等），被拉黑者看不到。
- **状态气泡与状态可见范围**：自定义状态可选「所有人（默认，和以前一样）/ 所有好友 / 星标好友 / 仅自己」（状态弹窗里的「谁可以看」）。手机首页快捷行里，好友当前有效的状态显示成头像上方的小气泡（emoji + 最多 12 个字，超出用省略号，最多两行）；点气泡会打开私聊，输入框里预填「回复了你的状态：“…”」（不会自动发送）。过期的状态不显示；被对方拉黑、在可见范围外的人读不到（服务器在 `custom_status()` 里统一判断，所有返回状态的地方都遵守；`status_emoji/status_text/status_expires_at` 原始列不再允许客户端直接读，好友气泡走 `list_friend_statuses()`）。
- **生日**（设置 → 我的资料 → 生日）：只存月和日，不存年份；默认仅好友可见，可改「仅自己」；可关掉「提醒我好友的生日」。资料页显示「生日 10 月 18 日」（只有有权限的好友看得到，被拉黑者看不到）。好友生日当天，通知页「全部 / 好友」里有「xx 今天生日」卡片，一键打开私聊并预填「生日快乐！🎂」；收件人设备当地时间 9:00（设备关机则到 20:59 前补发）推送一次，每个好友每年一次，按订阅的语言和时区，请勿打扰、已关提醒、被拉黑、已注销都不发。2 月 29 日的生日在平年按 2 月 28 日算。接在 `run_later_dispatch()` → `scheduled-dispatch`（`claim_birthday_pushes`），没有新增 cron。生日、支持链接随「导出我的数据」的资料文件一起导出，删除账号时清空。
- **共同好友 / 共同群聊 / 添加来源**：资料页新增「共同点」行（「3 个共同好友 · 2 个共同群聊 · 1 个共同圈子」）；对方是自己的好友时列出共同群聊的名字，对非好友只给数量（`get_mutuals`，遵守拉黑和资料可见范围；共同好友只算「双方都是好友」的人，机器人和已注销账号不算）。好友请求卡片（通知页、好友页）显示共同好友数（`get_mutual_counts`）。好友关系记录添加来源（搜索用户名 / 扫二维码 / 群聊成员列表 / 名片 / 圈子成员列表），资料页显示「来源」；发出请求时由页面入口上报（`set_friend_request_source`），「来自群聊」「来自圈子」会由服务器核对是否真有共同群/圈，核对不过就不记；同意后由触发器复制到好友关系。旧好友没有来源。
- **支持链接**（设置 → 我的资料 → 支持链接，圈子设置 → 支持页面）：个人资料最多 5 个链接，圈子 1 个；只能是白名单平台的 https 链接（爱发电 afdian.com / afdian.net / ifdian.net、Ko-fi、Patreon、Buy Me a Coffee、Liberapay、Open Collective、PayPal.me、pixiv FANBOX、Boosty、GitHub Sponsors 的 `github.com/sponsors/…`），服务器和客户端都校验（不接受仿冒域名、端口、用户名、空格）。点击先弹「即将离开 WeCord」确认，再用应用内浏览器（网页和没有内置浏览器的平台用新标签页）打开。WeCord 不经手钱。**iPhone 上整体隐藏**（App Store 3.1.1），网页（含 iPhone 的 Safari）、Mac 等显示。圈子成员在圈子菜单里看到「支持这个圈子」。
- **隐私权限 2.0**（设置 → 隐私与安全：「添加我」「群邀请」「通话」）：谁能向我发好友请求（所有人 / 朋友的朋友 / 共同圈子 / 无人，触发器强制）、能否通过用户名或二维码找到我（好友始终能找到）、谁能直接把我拉进群（所有好友 / 星标好友 / 需要我同意）、谁能给我打私聊电话（好友 / 星标好友 / 无人）。要求同意的拉群变成 `group_invitations`，7 天有效，通知页「好友」芯片里接受或拒绝；群二维码和名片是自愿加入，不受影响；私聊仍只限好友。
- **举报用户**：资料页可举报。

## 2. 导航与主界面

- **手机端**：左侧圈子栏 + 消息列表；顶部快捷行（添加好友、收藏、日程、朋友圈、日常、最近联系人；有日常的好友头像带强调色环，点一下直接看）；底部用户面板（头像、状态、通知铃铛）。
- **电脑端（≥840 宽）**：圈子栏 + 侧栏（好友、通知、收藏、朋友圈〔旁边是有新日常的好友头像环〕、日常、私信列表）+ 主内容 + 可拖拽调宽的右侧面板（资料 / 成员 / 笔记与清单）；macOS 标题栏留白适配。
- **快速切换器**：⌘K / Ctrl+K 搜索并跳转到任意会话、频道、笔记。
- **键盘快捷键**：上一个/下一个会话、Esc 取消回复或编辑并标记已读、空输入框按 ↑ 编辑上一条、跳到输入框、打开焦点消息菜单、显示快捷键帮助。
- **设置**：手机为整页，电脑为独立设置窗口（左侧导航，记住上次所在分区）。分区：我的资料、隐私与安全、外观、聊天、语音与视频、AI、通知、键盘快捷键、语言、账号。
- **聊天分组**（设置 → 聊天 → 聊天分组）：按规则建分组（私聊/群聊、仅未读、仅静音/排除静音、总是包含/总是排除的会话），最多 20 个，有「未读、群聊、私聊、已静音、折叠的群聊」模板；手机在「消息」标题下、电脑在私信列表上方显示可横滑的分组条，未读数为灰色，有人 @我 时显示红点；会话长按/右键「加入分组…」；「折叠的群聊」在列表里只占一行；分组规则存在服务器（`chat_folders`），多设备实时同步；置顶的会话在组内仍排最前。
- **文件传输助手**（Note to self）：固定在消息列表最上方、只有自己的会话，用于手机和电脑之间互传；无已读、无输入状态、不计未读、不推送。

## 3. 好友与社交关系

- **好友**：搜索用户名添加、好友请求（收到的请求在通知页和好友页顶部）、接受/拒绝、删除好友。
- **好友备注**：给好友设置只自己可见的备注名，聊天和推送里优先显示备注。
- **星标好友**：星标的人排在好友列表最前（「星标」分组）。
- **好友标签**：自建标签（家人、同事等），给好友打标签，按标签筛选好友；标签可用于朋友圈的可见范围。数据仅自己可见，删好友或拉黑后自动清理。
- **拉黑**：双向屏蔽私聊、朋友圈、在线状态、资料细节、拍一拍、名片等；被拉黑的人看不到你。
- **个人二维码**：设置和好友页里的「我的二维码」，样式化 QR（中间是头像），可保存图片、分享；码是不透明随机码（不是用户 ID），可「重置」使旧码立即失效。
- **扫一扫**：「+」菜单和好友页入口，支持相机扫码和从相册选图识别；能识别个人码、群二维码、圈子邀请、通话链接，其他内容显示为文本可复制。
- **群二维码**：群主/管理员在群详情生成，7 天有效，可刷新，生成者退群或被降级后自动失效。
- **名片**：在聊天「+」菜单发送好友或圈子的名片卡片；对方点开可加好友/发消息，或直接加入圈子（带 7 天邀请）；遵守资料可见范围和拉黑。
- **拍一拍**：双击对方头像（私聊和群聊），聊天里出现「你拍了拍 xxx」；可在设置里自定义后缀；2 分钟内可撤回；对方头像轻晃；有频率限制（同一对人 10 秒一次、每小时 20 次）；不推送、不算未读。

## 4. 会话类型

- **私聊**（1 对 1）。
- **群聊**：建群、群名、群头像、群公告、群主/管理员、管理员置顶、加人/移人、退群、群二维码；「批量退出不活跃的群」（30/90/180 天未活跃，6 秒撤销）。
- **圈子频道**（见第 10 节）：文字频道、论坛频道、公告频道、语音频道、舞台频道、话题（thread）。
- **文件传输助手**（见第 2 节）。

## 5. 消息：发送与输入

- **文字消息**：Markdown（粗体、斜体、删除线、代码、代码块、引用、列表、链接、剧透）；自定义 emoji。
- **@提及**：@用户、@角色、@everyone、@here（只提醒在线成员）；输入时有候选列表。
- **斜杠命令**：输入 `/` 出现命令列表，包括机器人注册的命令。
- **回复**：引用回复，手机上可左滑消息快速回复。
- **编辑**：可编辑已发送的消息（显示「已编辑」）；空输入框按 ↑ 编辑上一条。
- **编辑历史**：点气泡里的「已编辑」（或菜单里的「编辑历史」，读屏用户走这条）打开弹层，最新在上列出当前版本和每个旧版本及时间。旧版本由 `messages` 上的触发器写入表 `message_edits`（`edit_message` 没改），能看到消息的人才能看到历史；撤回、限时消息到期清理、阅后即焚（不可编辑）、账号删除时历史一起消失；搜索只索引最新版本。
- **草稿**：每个会话的草稿自动保存（停顿 400ms 写盘，切后台/切会话/发送时立即写入，不丢字）。
- **表情回应**：长按选 emoji 回应，回应列表可看谁回应了。
- **双击快捷回应**：双击消息直接点默认表情（可在设置 → 聊天里换成别的 emoji）。
- **贴纸**：圈子自定义贴纸，加上自己的「我的」表情包（A11）。
  - **添加**：图片、GIF（GIPHY）和贴纸消息的菜单里有「添加到表情」，预览后保存；设置 → 聊天 → 我的表情可从相册添加、拖动排序、删除。每人最多 300 个；静态图缩到长边 512 像素存成 PNG，动图（GIF/WebP）最大 1 MB，超过 1 MB 的 GIF 存成静态图；阅后即焚的照片不能添加。
  - **抠图**：添加时可以打开「抠出主体」。iPhone / Mac 用 Vision（`VNGenerateForegroundInstanceMaskRequest`，iOS 17 / macOS 14 以上，原生插件 `StickerCutoutPlugin`，通道 `wecord/sticker_cutout`），任何主体都行；网页复用通话背景虚化已加载的 MediaPipe 人像分割模型（`web/stickers/cutout.js`），只认人像。图片都在本机处理，不上传；系统不支持时不显示这个开关。
  - **发送**：贴纸面板有「我的」和「圈子」两个标签（圈子频道默认先开圈子）；私聊、群聊、频道都能发。库存放在私有存储桶 `user-stickers`（`<用户id>/…`，只有本人能读写）；发送时先把文件复制到该会话文件夹的 `chat-images`，再调用 `send_personal_sticker`，消息仍是 `sticker` 类型，附件带 `personal: true` 和复制件的路径。所以别人读不到你的表情库，只有收到的那一份。减少动态效果时动图停在第一帧；举报（A1）照常覆盖。
- **GIF**：内置 GIPHY 搜索（手机上在「+」菜单）。
- **投票**：单选/多选、匿名投票、测验模式（正确答案只对已投票者/发起人/结束后可见）、截止时间、允许他人添加选项；投票结果实时更新。
- **语音消息**：按住录音，波形显示；录音 WAV；最长 9 分钟，最后 30 秒倒计时，到时自动停止并发送；超大时提示「语音消息太长」；播放器在首次点播放时才创建。
  - **倍速与连播**（A10）：播放时出现「1× / 1.5× / 2×」小按钮，点一下依次切换，速度保留到下一条；同一时间只播一条，暂停后记住位置；一条播完自动播放聊天里下一条别人发的、没听过的语音（设置 → 聊天可关「连续播放语音」；下一条的气泡不在屏幕附近时就停下）。
  - **暂停续录与裁剪**（A10）：录音时可「暂停 / 继续」（暂停的时间不计入 9 分钟）；暂停后点剪刀「裁剪」，在波形上拖动两端、可试听，发送的只是保留的那一段（直接按采样截取 WAV，不经服务器）；暂停后继续录会清掉已选的裁剪。录音器不支持暂停时不显示按钮。
- **引用部分文字回复**（A9）：消息菜单「回复所选文字」打开原文，选中一段后回复；气泡里的引用块显示这一段（而不是消息开头），点它跳到原消息并高亮。服务端（触发器 `messages_check_reply_quote`）检查引用确实是原消息的一部分（同一会话、未撤回、未过期、发送者看得见），1–500 字，只保留 `text/start/end`；原消息被撤回时，回复里的引用一并清掉。
- **静默发送**（A9）：「+」菜单「静默发送」，消息照常显示、算未读，但不推送给任何人（`messages.silent`，只能在发送时设置；`push` 和 `scheduled-dispatch` 在发送前丢掉静默消息的推送，不依赖 Web Push 的 `silent` 标志，因为 Safari 会忽略它）；自己的静默消息下方有「已静默发送」。不经发件箱，所以需要联网；命令不能静默发送。
- **关键词特效**（A12）：消息里出现「生日快乐 / 新年快乐 / 恭喜 / 想你了 / 干杯 / 晚安」及英文对应词时，聊天上方飘一次 emoji（最多 36 个，一个动画驱动一个画笔，不重建列表）。只对刚收到/刚发出的消息播（30 秒内），每条只播一次（本机记住最近 200 条），开启「减少动态效果」或在设置 → 聊天关掉「关键词特效」时不播；读屏不朗读、不挡点击。
- **语音转文字**（见第 12 节 AI）。
- **语音输入**（说话变文字）：输入框旁的声波按钮，点一下开始/再点结束，或按住说话；实时把文字写进输入框；中英文切换；iPhone/Mac 本机识别（`SFSpeechRecognizer`），不支持本机识别时先征求同意再交给 Apple 服务器；网页用浏览器 Web Speech API（首次使用会提示由浏览器厂商的服务处理）。设置 → 聊天可隐藏该按钮。
- **消息里的时间（时区令牌）**：输入「明天晚上8点」「下周三下午3点」「in 2 hours」等会提示转换；转换后的时间按每个读者自己的时区显示，可点开查看完整时间、加入日历（网页下载 .ics，Apple 平台用分享）、复制。推送里也会按收件人时区和语言格式化。
- **定时发送**：选择发送时间，到点由服务器自动发出（即使你离线）；发出前可编辑、立即发送、删除；失败会标记原因。
- **重复的定时消息**：选时间的弹层里有「重复」：每天 / 工作日 / 每周（第一次发送的那个星期几）/ 每月（第一次发送的那个几号），可设结束日期（含当天，最长两年）。按**发送者设备时区的墙钟时间**算：每周一 9:00 在夏令时变化后仍是 9:00；落在被跳过的那个小时（如 02:30）会顺延到间隙之后（03:30），落在重复的那个小时（01:30）只在第二次（标准时间）发一次。每月 29/30/31 号遇到没有这一天的月份，改在**当月最后一天**发，下个月再回到原来的号数。工作日的第一次若选在周末，顺延到周一。列表里每条显示「每周一 9:00 AM」「截止 …」，删除下一条就等于停止重复。同时最多 20 条重复消息。服务器：`scheduled_messages` 加 `recurrence/recurrence_day/recurrence_time/recurrence_tz/recurrence_until/recurrence_parent_id`；任何一条发出（或失败）后，触发器写下一条（`recurrence_parent_id` 唯一索引保证一条只生成一条）；消息的 `client_id` 仍是定时行的 id，重试不会重复发送；晚到（比如宕机几天）只补发一条，下一条从「现在之后」算；发送者退群则系列结束；下一条会出现在「我的日程」里。
- **链接预览**：自动抓取标题、描述、图片；同时判断链接风险（见第 12 节的链接安全检查）。
- **离线发送（发件箱）**：没网时消息进入本地发件箱，联网后自动补发；本地聊天缓存（手机/电脑 SQLite，网页 IndexedDB）可离线浏览聊天记录；顶部显示连接状态条。
- **发送失败处理**：失败的消息可重试、编辑后重发。

## 6. 消息：查看与操作

- **消息菜单**（长按 / 右键 / 悬停「更多」）：回复、回应、复制、编辑、转发、添加到表情（图片、GIF、贴纸）、置顶、收藏（稍后看）、提醒我、创建任务、开话题、选择（多选）、翻译、转文字、复制图片中的文字、删除/撤回。
- **撤回 / 删除**：撤回自己的消息（附带内容一并从存储擦除）；版主可删除他人消息。
- **转发**：单条转发到其他会话（显示「转发自 xxx」）。
- **多选**：进入多选模式后可批量转发、合并转发、收藏、复制、删除（只能删自己的，或你是版主）；最多 100 条；电脑上 Shift 连选、Esc 退出。
- **合并转发（聊天记录）**：把多条消息合成一张「聊天记录：xxx」卡片，对方即使不在原会话也能打开只读查看（含图片和文件）；阅后即焚、已过期、审核中、投票、贴纸、系统消息不能放进去；只能发到私聊和群聊（不能发到圈子频道，因为审核看不到卡片内容）；嵌套最多一层。
- **置顶消息**：频道/群/私聊置顶，置顶列表。
- **已读回执**：私聊显示「已读」；群里（200 人以内）在自己最新一条消息下显示灰色「N 人已读」，群不会再因为一个人读了就显示「已读」。圈子频道、话题、文件传输助手不显示。
- **群已读名单**：点「N 人已读」或消息菜单里的「消息信息」（读屏用户走这条，仅限自己发的群消息）打开弹层：已读 / 未读两栏（手机上是切换），关闭了已读回执的人归在「未知」。只有发送者能看；被拉黑的人不在名单里；新入群的人不在名单里；撤回、已过期、审核中的消息没有名单。比较方式：成员 `last_read` 指向的消息的 `created_at` ≥ 这条消息。名单打开时才查询（`get_message_read_status`），不实时推送。
- **提醒未读的人**：名单里的「提醒未读的人」（`remind_unread`）给未读的人各发一条推送（按每台设备的语言和时区写，消息时间用时间标记），并在通知页「提醒」里生成卡片（读了这条消息或点「关闭」后消失）。每条消息只能提醒一次，每人每天最多 30 次；「未知」的人和勿扰（DND）的人不推送；免打扰时段（A4）照常拦截，提醒不属于任何例外。推送走 `push` 函数的 `read_reminder_message_id`。
- **加急消息**（消息菜单「加急」，只能对自己发的消息；私聊和群聊，圈子频道不提供）：发送者选最多 10 个会话成员（服务器强制：只能是成员；自己、机器人不算；拉黑关系、对发送者关闭了加急的人会被悄悄略过，没人可通知时报错，所以和被拉黑的人私聊里用不了）。每人 24 小时内最多 5 次（滚动计算，服务器强制），弹层里显示还剩几次，也列出这条消息已加急过的人以及谁已确认。被加急的人立刻收到一条推送，**能突破免打扰时段、会话/圈子静音和「请勿打扰」状态**（`claim_urgent_pushes`，调度函数发送时不对它做免打扰时段过滤），但仍遵守拉黑、对发送者关闭加急、退群、账号删除、消息被撤回/过期/审核中，文字按每台设备的语言写；聊天顶部出现**红色横幅**「xx 加急了一条消息」，带「知道了」「跳转」「不再接收 xx 的加急」，通知页的「待确认」分类里也有卡片，两处都计入铃铛角标。10 分钟内没点「知道了」，再推送一次（只再推一次，同一个 tag 替换第一条）；一小时后的不再补。「设置 → 通知 → 加急消息」列出关闭了的人，可重新允许。不做短信和电话加急。
- **需要确认的群公告**：群主/管理员在「群资料」里打开「需要成员确认」（群公告必须非空；只在群聊，私聊没有公告，圈子频道的话题不是公告）。公告条下面显示「已确认 12/30」；没确认的成员有「确认」按钮；群主/管理员有「谁确认了」弹层（未确认/已确认两栏、时间）和「提醒未确认的人」（给没确认的人推送并算作一次提醒，**每个群 6 小时一次**；被拉黑和机器人不提醒；打开时已提醒一次）。改了公告文字或关闭开关会清空确认，重新开启从头计。普通成员只能看到总数和自己的状态，看不到别人的名单。提醒推送遵守免打扰（请勿打扰、会话静音、免打扰时段都会拦下，不属于「加急」）。服务器：`set_announcement_requires_ack`、`ack_announcement`、`get_announcement_ack_state`、`list_announcement_ack_members`、`remind_announcement_unacked`、`list_my_pending_announcement_acks`；`update_group_profile` 没改。
- **发送已读回执开关**：设置 → 隐私与安全 → 「发送已读回执」（`user_privacy_settings.send_read_receipts`，默认开）。像 WhatsApp：关掉后别人看到你是「未知」，你自己也看不到别人的回执（群里的名单和私聊的「已读」都一样）。服务端通过 `list_read_markers` 把这类人的读到位置清空；超过 200 人的群、频道、话题只返回自己的位置。
- **正在输入**：显示「xxx 正在输入…」（通过私有实时通道，只有成员能收到）。
- **未读分隔线**：「NEW」分隔线标出未读开始位置。
- **消息分页加载**：向上滚动按页加载历史；搜索结果可跳转到上下文。
- **相册**：一次发多张图/视频合成相册网格；会话列表和推送按「一组」计算，不会一张一条。

## 7. 媒体、文件与预览

- **图片**：多选、拖放、粘贴剪贴板；发送前在托盘里预览；默认压缩到 2560px 并去掉 GPS/相机元数据，可选「原图质量」；blurhash 占位；聊天里按显示尺寸解码以节省内存。
- **发图前编辑**：托盘里每张图有 ✏️ 编辑：涂鸦（8 色 3 粗细、撤销重做）、文字（可移动缩放旋转、颜色、背景胶囊）、马赛克/模糊笔刷、裁剪（自由/1:1/4:3/16:9、旋转 90°）；支持触屏、鼠标、触控板捏合；⌘Z / ⇧⌘Z；全部撤销会恢复原图。
- **视频**：发送、海报帧、应用内播放（拖动、倍速、全屏）。
- **文件**：任意类型，单个上限 50MB。
- **应用内文件预览**：
  - 图片、视频、音频、PDF（pdfrx）、纯文本、CSV 表格、代码（40 种语言语法高亮，网页按需加载）；
  - Word / PowerPoint / Excel：iPhone/Mac 用系统 Quick Look 原生预览；网页由 Gotenberg（Google Cloud Run）转换成 PDF 后预览，转换结果缓存在私有存储；
  - 预览里可下载、分享、用其他应用打开。
- **图片描述（ALT）**：发图时托盘里点「描述图片」，可为每张图写一段描述（最多 1000 字，给读屏用户和看不清图的人）；描述存在附件 JSON 的 `alt` 里，聊天里的图片带 ALT 标记（点开看全文），读屏读「图片：描述」而不是文件名，查看器读描述；一次性查看的图不带描述；合并转发保留描述（迁移 `202610250510`）。「AI 生成图片描述」未做（等图片模型定下来）。
- **视频字幕（本机生成，仅 iPhone/Mac）**：视频查看器里点 CC，用系统语音识别在本机把视频的声音转成带时间的字幕（不上传声音；设备不支持该语言时不走苹果服务器，直接提示没有字幕）；打开后之后的视频自动出字幕，结果缓存在本机（每个账号最多 20 个）。网页不显示 CC 按钮。
- **图片文字识别（OCR）**：长按图片或在查看器里点「复制图片中的文字」；iPhone/Mac 用 Apple Vision 本机识别（中文简繁 + 英文），图片不上传；可复制、选择、翻译；网页不支持（会提示去 App 里用）。
- **会话媒体页**：按会话浏览所有图片、视频、文件（`/chats/:id/media`）。
- **应用内浏览器**：链接可在应用内打开。

## 8. 搜索

- **全局消息搜索**（`/search/messages`）：全文搜索，筛选条件（来自谁、在哪个会话/频道、是否有附件、日期范围等）带候选提示，结果高亮、跳转到上下文，最近搜索记录。
- **会话内搜索**：聊天顶栏的搜索框。
- **快速切换器**：会话、频道、笔记标题。
- 搜索遵守所有可见性规则（过期消息、审核中消息、无权限频道都搜不到）。

## 9. 效率与协作工具

- **收藏（稍后看）**：消息菜单「收藏」，收藏页（`/saved`）可标记已完成、移除；手机首页和电脑侧栏都有入口。
- **收藏 2.0**（收藏页 `/saved`，迁移 `202610250400`–`202610250430`）：从「稍后看」升级为个人资料库。
  - **数据**：通用表 `saved_items`（`kind`：message / moment / circle_post / link / note / text；`target_id`、`folder_id`、`tags text[]`、`note` 备注，笔记另有 `title`、`body`、`images`；全部数据只有本人能读、能删，写入只走 RPC）和 `saved_folders`（最多 50 个、同名不分大小写合并）。旧的 `saved_messages` 迁入新表（id、已完成状态都保留），并留下同名只读视图 `saved_messages`，老版本 App 照常列出、标完成、移除；`list_saved_messages` / `save_message` / `set_saved_message_done` 签名不变。最多 1000 项，每项最多 10 个标签（去 `#`、折叠空格、最长 24 字、不分大小写去重）。
  - **只存引用**：消息、朋友圈、圈子帖子只存 id，每次实时读取（`list_saved_items` 以调用者身份运行，沿用各自的行级权限）。原消息被撤回、过期、被 AI 守护扣留，朋友圈被删/设为私密/取消好友/被拉黑/被隐藏，帖子被删/退出圈子/圈子被封，条目显示「内容已不可见」且不返回任何文字，只能整理或移除；阅后即焚消息不能收藏（旧数据读不出内容）。朋友圈经 `moments_post_visible_to`，帖子要求是圈子成员且圈子未被封停。
  - **自己的内容**：链接（`save_link`，只收 http/https，同一地址只存一次）、笔记（`create_saved_note`：标题 / 文字 / 最多 4 张图，只有文字没有标题时叫「文字」）。图片放私有桶 `saved-notes`（JPEG、5MB、路径 `<用户>/<条目>-<0..3>.jpg`，只有本人读写，删除条目时 App 一并删文件，删号时清空整个文件夹）。
  - **搜索**：`search_saved_items`：每个词都要命中——本人文字（标题、文字、备注、链接、标签；`search_vector` 用 `search_split_cjk` 把每个汉字拆开，另加子串）或所指内容当前的文字（只在看得见时）。不为别人的文字做快照。
  - **界面**：收藏页顶部「待处理 / 完成」、分组芯片（带数量，长按重命名 / 删除，删除分组不删内容）、标签芯片（长按重命名 / 删除标签），搜索框（搜索时跨「待处理 / 完成」）；右上「+」新建笔记、保存链接、新建分组；每张卡显示类型、分组、标签、备注，可打开（消息跳转、朋友圈、圈子、链接用应用内浏览器 / 系统浏览器）、标记完成、编辑（分组、标签、备注，笔记可改标题、文字、去掉图片）、移除。朋友圈卡片和圈子帖子菜单加「稍后再看 / 从已保存移除」。
  - **导出与删号**：`export_my_saved_items`（服务端密钥调用）→ `data/favorites.json` 和 `pages/favorites.html`（别人写的文字不收，笔记图片给限时链接）；删号由 `profiles.deleted_at` 触发器清空条目和分组，`delete-account` 的 `userBuckets` 加了 `saved-notes`。
- **提醒我**：对某条消息设提醒（快捷时间或自选），到点出现在通知页的「提醒」并推送；可查看即将到来的提醒。
- **定时发送**（见第 5 节）。
- **我的日程**（`/agenda`）：把我报名（去/可能）的群活动、感兴趣的圈子活动、指派给我且未完成的任务、我设的提醒、我待发的定时消息合在一个页面；列表分「需要你处理（逾期，红色）/ 今天 / 明天 / 本周 / 以后」，也有月历视图。数据来自 RPC `get_my_agenda(from, to)`，沿用现有可见规则：退群、退圈、被拉黑的私聊、已过期或被 AI 守护拦下的消息，对应条目都不会出现（提醒保留但不显示正文）。电脑侧栏「日程」行、手机首页快捷行一格、快速切换器输入「agenda」都能进入。
- **日历订阅**（设置 → 日历订阅）：生成一条保密链接 `…/functions/v1/calendar-feed/<令牌>.ics`，在苹果日历 / 谷歌日历订阅后看到未来 60 天的活动和任务。令牌是 192 位随机数，服务器只存 SHA-256 哈希，不含用户 ID，可随时重置（旧链接立即失效）或关闭；默认只输出「时间 + 会话名」，勾选「包含标题和详情」才写入正文；每条链接每小时最多 30 次请求。函数 `calendar-feed` 的 `verify_jwt = false`，令牌在数据库函数 `calendar_feed_items` 里校验。
- **共享笔记**（类似 Slack Canvas）：
  - 每个会话（私聊、群、频道）都能建多篇笔记；电脑上在右侧面板打开，手机上整页（`/chats/:id/workspace`）。
  - 块编辑器：段落、标题 1–3、无序/有序列表、待办、引用、代码块、分割线、图片；Markdown 快捷输入（`# `、`- `、`[] `、`> ` 等），`/` 块菜单，⌘B/I/E、⇧X、K 快捷键，@提及。
  - 多人实时协作：能看到别人的光标和名字；冲突按块三方合并，不丢字；离线编辑保存在本机，联网后自动合并。
  - 历史版本：自动快照（安静 10 分钟后的首次修改、持续编辑每 30 分钟、手动），可恢复。
  - 置顶笔记（聊天顶部横幅）、「仅管理者可编辑」、分享到聊天成卡片、快速切换器可搜标题。
  - **表格块**：`/` 菜单或块菜单插入表格（最多 12 列、200 行，单元格 1000 字），行列有各自的 id，两个人改不同单元格互不覆盖，同一格同时改会把两边的字都保留；可加/删行列、切换表头行；导出 Markdown 是标准表格。
  - **评论**：选中文字点格式栏的评论按钮（或评论整段、整篇笔记）；被评论的文字高亮、该段右侧显示未解决条数；头部评论按钮显示未解决的讨论数，打开后分「未解决 / 已解决」，可回复、解决/重新打开、编辑自己的、删除（作者或管理者）。评论里可 @ 成员，被提到的人和被回复的人在通知页收到一张评论卡（算「提及 / 回复」，不推送）。权限：能看笔记的人读；能在该会话发言的人写（「仅管理者可编辑」的笔记照样可评论）；拉黑双方互相看不到对方的评论；圈子被下架（Suspend）后读写都不行；引用的原文必须真在那一段里，不能伪造。删除笔记会一并删除评论。
  - **模板**：新建笔记先选「空白 / 会议纪要 / 周报 / 旅行计划 / 我的模板」；笔记菜单「存为模板…」存成个人模板（图片和 @提及不存，最多 30 个，只有自己看得到）。
  - **导出**：笔记菜单「导出为 Markdown 文件」「导出为 PDF」（网页直接下载，Apple 设备走分享面板）。PDF 用设备自己的字体逐页画成 A4 图片再装进 PDF（中文、emoji 都正常，代价是文字不能选中；单个文件里图片也会带上）。「复制为 Markdown」仍在。
  - **发布到网页**：笔记菜单「发布到网页…」，只有能编辑该笔记的人可以发布；默认关闭，发布前会提示「任何拿到链接的人都能看，不需要账号，评论和历史版本不显示」。链接是 `https://<站点>/n/<令牌>`（192 位随机令牌，每篇笔记一个，随时「停止分享」，再发布是新链接，旧链接永远失效）；网页是只读的，不含评论、历史、人名；@提及被去掉，只有 http/https 链接可点，图片是 1 小时有效的签名链接。默认带 `noindex`（搜索引擎不收录），作者勾选「允许搜索引擎收录」才放开。笔记被删、圈子被下架、发布者退出会话或注销，链接立刻失效（所有失效原因对访客看起来一样）。读取走 Edge Function `note-public`（`verify_jwt = false`，令牌在数据库函数里校验，错误令牌按地址限频），页面由网页版 App 的公开路由 `/n/:token` 绘制（Supabase 的函数域名不会把 HTML 当网页显示，所以不是服务端 HTML）。
  - **笔记 AI**：`/` 菜单「AI…」和格式栏的 ✨：续写、总结、生成提纲、改语气、翻译、提取待办；对选中的文字或整篇笔记；结果先预览，选「添加到下面」或「替换所选文字」才写入（先自动存一个「AI 修改之前」的历史版本）。遵守圈子和本人的 AI 开关与每日额度，见 `docs/ai-setup.md`。
- **任务清单**（类似 Slack Lists）：
  - 列表视图（按状态分组，筛选：全部/我的/逾期/未完成，排序）和看板视图（按状态分列，拖拽移动，长按拖动，边缘自动滚动，读屏可用「移动到…」）。

  - 按字段更新（两人改不同字段互不覆盖）；离线修改保存在本机，重启后自动补发。
  - 从消息创建任务（消息下方显示任务和勾选框）；任务卡片可直接在聊天里勾选完成。
  - 指派通知、即将到期/已逾期提醒（通知页「任务」分类 + 推送）。
  - **任务清单 2.0**（迁移 `202610250100`–`0130`）：
    - **自定义字段**：列表菜单「自定义字段」（能编辑列表的人），最多 20 个，类型：数字、单选（最多 30 个选项）、链接（只收 http/https）、人员（必须是会话成员）。任务面板里逐个填写，列表行和看板卡片显示有值的前 3 个。两人改不同字段互不覆盖（服务器按字段合并，`null` 清除某个值）。改字段类型、删字段、删选项后，已有任务里不再合法的值会被清掉；离线补发时指向已不存在字段或不合法的值被忽略，不会让整条修改被拒。字段值不进推送；数据导出带字段定义和自己建的任务的值（`data/task_extras.json`）；账号注销后，人员字段里的该用户被清除。
    - **子任务**：任务面板「子任务」区加/勾选，点子任务进入它自己的面板（顶部「某某的子任务」可返回）。只有一层，每个任务最多 50 个，必须在同一清单；列表里缩进在任务下，看板只显示任务并带「完成数/总数」。筛选时任务不匹配但子任务匹配，任务仍显示；删任务会删它的子任务。子任务不能重复。
    - **重复任务**：任务面板「重复」选每天/每周/每月/每年或每 N 个，需要有截止日期（没有时自动设为今天）。完成时由数据库触发器生成下一条（复制标题、备注、优先级、字段、负责人，子任务重置为未完成，状态回到第一个「未开始」，同一条只生成一次，所以取消再勾选不会重复生成）；下一条日期是规则里「现在之后」的第一个日期，逾期很久完成不会生成一堆过期任务。全天任务始终在当地当天 23:59，跨夏令时也不漂（用规则里的时区偏移，设备所在时区在服务器已知时用 IANA 时区）；每月的 31 号在短月落在月底，之后回到 31 号。新生成的任务不推「被指派」通知，到期提醒照常。离线完成时下一条要等补发成功后才出现。
    - **日历视图**：头部的视图按钮（列表 / 看板 / 日历）。月历复用「我的日程」的月格（`MonthDayCell`），每天最多 3 个点、有逾期显示红点；点某天看当天任务，下方「为这一天添加任务」直接建（截止当天 23:59 全天），底部列出没有日期的任务。筛选对日历同样有效。日历是本机的看法，不是清单的默认视图。
    - 头部只有「视图」「更多」两个按钮；大字号下任务面板的字段行改成标签在上、值在下。
- **群接龙**：群聊或频道「+」→「接龙」；标题、说明、示例行、截止时间、人数上限；卡片显示编号名单（前 6 行），点「加入」可附一句备注，可修改/删除自己的一行；名单实时更新、不刷屏；发起人和版主可移除行、关闭/重新开放；所有人可复制/分享名单。私聊不能发起。

## 10. 圈子（Discord 式社区）

- **创建圈子**：空白创建或从模板创建（模板码，可同步更新）；圈子名、头像、描述、标签（如「像素艺术」）、语言、分类。
- **频道与分类**：文字频道、论坛频道（帖子 + 标签 + 帖子内 @提及）、公告频道（可被其他圈子关注，通过 webhook 转发）、语音频道、舞台频道；频道分类（可折叠、记住折叠状态）；频道主题、私有频道、只读频道。
- **话题（Threads）**：从消息开话题，话题列表；话题创建者或圈主/管理员可归档；有「管理消息」权限的版主可**锁定**话题或论坛帖子（话题页菜单「锁定话题」）：锁定后所有人还能读和加表情，但只有版主能发言，输入框换成「这个话题已锁定，只有版主可以回复」；锁定和解锁写审计日志；发送由 `messages` 上的触发器拦下，所有发送路径（含定时发送、转发）都挡住。
- **角色与权限**：
  - 角色（颜色、排序、可单独显示、可被 @提及），按角色分配权限；
  - 权限项：查看频道、发送消息、管理消息、管理频道、管理角色、管理昵称、管理表情、管理活动、管理 webhook、创建邀请、踢出成员、@everyone、连接语音等；
  - 频道权限覆盖（按角色或成员允许/拒绝/继承）；只能管理比自己低的角色。
- **成员管理**：邀请（链接 + 二维码）、踢出、封禁（**可限期**：永久 / 1 小时 / 1 天 / 7 天 / 30 天，到期自动解封）、禁言/超时、圈子内昵称、成员列表（按角色分组，在线/离线）、退出圈子。
- **版主工具 2.0**（C5；圈子设置或圈子菜单 →「成员」）：
  - **限期封禁**：`circle_bans.expires_at`；独立的 pg_cron 任务 `wecord-circle-safety-sweep`（每分钟，不改 `run_later_dispatch()`）解封并写 `member_unban_auto` 审计；入圈守卫触发器遇到已到期的封禁也会当场解除。封禁弹窗选时长；封禁列表显示「永久 / 某时结束」和「有申诉待处理」。
  - **版主备注与警告**（`circle_mod_notes`，需要「禁言成员」权限，只能处理排位比自己低的人）：成员行菜单「版主备注」，或成员页点一行；备注和警告只有版主看得到，被警告的人不会收到通知；审计日志只写「添加了备注 / 警告了某人」，不写内容。
  - **成员筛选与批量处理**：按加入时间、账号年龄、圈内发言数、角色、是否被标记（有警告、有未处理举报、或消息被 AI 守护扣留/标记）和名字筛选；每行告诉你对这个人能不能禁言/踢出/封禁（权限和排位）；点「选择」后一次最多 50 人批量禁言、踢出、封禁。批量复用单个操作的函数，排位更高的人会被单独拒绝而不影响其他人，并多写一条 `member_batch_action` 审计。
  - **封禁申诉**（`circle_ban_appeals`）：被封的人在通知页「圈子」看到卡片和「申诉这次封禁」（每次封禁只能申诉一次，再封一次可以再申诉）；有「封禁成员」权限的版主在「审核」页的「封禁申诉」（红色计数）批准（解封）或驳回（可附理由）；不能推翻排位比自己高的人做的封禁；结果推送给申诉人。封禁理由不会给被封的人看。
- **突袭防护**（C6；圈子设置 →「突袭防护」、圈子菜单 →「安全动作」；需要「踢出成员」或「管理圈子」）：
  - **安全动作**：暂停邀请 1 / 24 小时（邀请链接、名片邀请、成员加好友全部停用，不影响探索页加入）；入圈锁门 1 / 24 小时 =  暂停邀请 + 开放圈子临时改成「申请加入」（C1），**不踢任何人**。
  - **自动触发**：10 分钟内加入或申请加入的人数达到阈值（默认 20，圈子可设 3 到 500，也可关闭），或其中的新账号（不到一天）达到阈值的一半（至少 5 个）时自动锁门（锁 1 或 24 小时）。事务提交时才检查，所以批量加好友不会被半路拒绝；不到一小时的新圈子不触发。
  - **提醒与解除**：往 AutoMod 告警频道发一张「突袭防护」卡片（圈子有告警频道时），推送给圈主和有「踢出成员 / 管理圈子」权限的角色成员，审核页顶部横幅一键「解除锁门」。到期自动解除，并把加入方式恢复成锁门前的样子；锁门期间如果有人手动改了加入方式，以他的选择为准。全部写审计（`raid_lockdown`、`raid_release`、`invites_pause`、`invites_resume`、`raid_settings_update`）。
  - **和别的功能的协调**：锁门期间进来的人（批准的申请也算）在锁门结束前不能发链接；圈子开了 AI 守护时，他们的消息也交给 AI 守护检查（不管守护自己的「谁算新人」规则）；规则确认（C2 引导）、申请审核（C1）、封禁照旧；圈子被 K1 下架或封停时，所有版主操作被拒绝。
- **慢速模式**：频道级发送间隔。
- **AutoMod**：关键词/正则规则、垃圾信息、提及轰炸限制（每条消息唯一提及数、时间窗口内消息数），动作：拦截消息、发送警报到指定频道、超时成员；可豁免角色和频道；被拦截时发送者看到提示卡片。
- **新成员 AI 守护**（见第 12 节）。
- **成员引导（Onboarding）**：必须接受规则才能发言、回应、加入语音；欢迎消息。
- **新人指南（引导 2.0）**（圈子设置 → 引导 → 新人指南；需要「管理圈子」）：圈子可以问新人最多 5 个问题（每题最多 12 个选项，可设必答、单选或多选），选项能给角色（每项最多 5 个）并指向频道（用现有的频道权限覆盖让某些频道只对某个角色可见）；再加最多 10 个新人任务（阅读规则、去某个频道、在频道发一条消息、设置头像，进度由服务器按成员自己的状态算出，「去某个频道」由应用确认）。新人接受规则后问题页自动打开一次（只对在指南建立之后加入的成员；老成员从圈子菜单「新人指南」进入），回答之后随时可以改；圈子顶部有「新人指南」卡片和进度条，做完或隐藏后消失。可选的「欢迎卡片」：新人入圈时在指定频道出现一条系统消息，带「打招呼」按钮，点一下发圈子的欢迎贴纸（没设就发一个挥手）。**安全**：问题只能发放不含管理权限的角色——只允许 `view_channel`、`send_messages`、`create_invites`、`connect_voice`（连 `mention_everyone` 也不行），不能是 @everyone，也不能排在任何有管理权限的角色之上（否则会让人躲开版主管理）；服务器在挂角色时（触发器）和每次有人答题时都重新检查，所以角色后来被加上管理权限后不会再被发出去，同时自动取消选项上的链接并收回通过答题得到的这个角色（管理员手动给的保留）；给选项加新角色还需要「管理角色」且角色低于自己；答题发放写审计（`onboarding_roles`，注明来自引导）；圈子下架（suspend）时一律拒绝；表格客户端不可读，只能通过 RPC（`get_circle_guide`、`complete_onboarding_prompts` 等）。
- **入圈申请与审核**（圈子设置 → 入圈方式）：开放 / 申请加入 / 仅限邀请。申请模式下，邀请链接、名片里的 7 天邀请、探索页加入、成员邀请好友都变成申请（`circle_join_requests`），最多 5 个文字或单选问题；有「踢出成员」权限的版主在「审核」页的「入圈申请」（红色计数，和 AI 守护队列同页）批准或拒绝，可附理由，写审计日志；申请人在通知页「圈子」看到结果并收到推送（按设备语言和时区），批准后走规则确认和欢迎消息。同时有「创建邀请」和「踢出成员」的人可建「免审核」邀请，成员邀请好友也免审核；封禁、圈子下架照常拦截；拒绝后一天内不能再申请。`circle_members` 上的触发器兜底：任何忘记检查入圈方式的路径会被拒绝，而不是绕过审核。
- **圈子数据看板**（圈子设置 → 数据；需要「管理圈子」或「查看审计日志」，圈主和管理员自带）：7 / 30 / 90 天的成员数折线、每日消息和活跃成员柱状、「星期 × 小时」热力图（按你的时区）、频道排行、邀请链接排行、谁带来了新人，以及两个留存比率（新人仍在圈内、上周回访）。每天 00:10 UTC 由 pg_cron 聚合昨天（`circle_daily_stats`、`circle_member_daily` 只记当天是否活跃，不存内容；加入、退出、语音时长由触发器随时累加）。隐私：1 到 4 的数字一律显示「<5」；成员不足 5 人的圈子所有数字都隐藏；留存只给比率，且至少 5 人才给；邀请排行只显示创建者和日期，不返回邀请码；表格客户端不可读，只能通过 `get_circle_insights`。机器人、Webhook、系统消息（如新人欢迎卡片）、已撤回和被 AI 守护拦下的消息不计入。
- **邀请追踪**：`circle_members.joined_via_invite` 和 `invited_by` 记录每个人是通过哪个邀请链接、哪位成员进圈的（包括申请模式下由邀请产生、之后被批准的申请；批准人不会被记成邀请人）；`circle_invite_joins` 按每次进圈留一行，所以「带来 12 人 · 仍在 9 人」里离开的人也算带来。邀请列表每条链接显示这两个数字，数据看板有邀请排行。靠触发器接在 C1 的三条入圈路径上，没有重写它们。
- **自定义表情与贴纸**：圈子上传 emoji / 贴纸，消息里使用，实时生效。
- **圈子动态（Feed）**：圈子内发帖、点赞、评论。
- **圈子活动**：创建活动、报名、「正在进行」标识、下载日历文件（.ics）。
- **审计日志**：管理操作记录（含 AI 守护的 5 种操作），可按类型筛选。
- **通知设置**：每个圈子的通知级别（全部 / 仅 @ / 无）、静音时长。
- **未读计数**：圈子栏和频道列表的未读数（普通未读为灰色；@提及等需要你处理的为红色）。
- **发现**（`/discover`）：公开圈子列表（最热、最活跃、按分类和标签筛选），圈子发现设置（是否公开列出），举报公开圈子。
- **公开圈子网页 + 漂亮的邀请链接（C8）**：公开圈子在「圈子设置 → 发现 → 网页」可设一个**短名**（`circles.slug`，全站唯一，3–32 位小写字母/数字/连字符，`admin`、`invite`、`wecord` 等站点自用词保留；圈主/有 `manage_circle` 的人才能改，每小时最多改 10 次，写入审计日志 `slug_update`）。链接 `https://<站点>/c/<短名>` 和邀请链接 `https://<站点>/invite/<邀请码>`（分享邀请时现在生成这种路径形式，旧的 `/#/invite/<码>` 仍可用）由 Cloudflare Worker（`worker/src/`，`wrangler.jsonc` 的 `main`）在服务器端画成 HTML 卡片：带 Open Graph 信息，微信/Telegram 等里显示圈子名、头像、简介；没装 App 的人也能看到介绍，按钮「在 WeCord 中加入/申请加入/打开」跳到网页版 App 的 `/#/invite/<码>`（C1 申请入圈、C4 邀请归因照常生效）或 `/#/c/<短名>`（成员直接进圈子，其他人看到和发现页一样的预览）。数据只来自两个对 anon 开放的只读函数 `get_public_circle_card(slug)` 和 `get_public_invite_card(code)`：只返回名称、简介、头像（仅 https 地址）、分类、语言、标签、加入方式和**成员数级别**（少于 5 人不显示，否则取 5/10/25/50/100/250/500/1000/2500/5000/10000 中不超过实际人数的最大值），不返回 id、成员或频道。**只展示公开且未被下架/封停的圈子**，私有圈子（即使邀请有效）、被下架或封停的圈子、失效（撤销/过期/用完/被突袭防护暂停）或不存在的邀请码、格式不对的值，全部返回同一个「此页面不可用」（404，页面内容一样，不泄露是否存在）。页面按 `Accept-Language`（也可 `?lang=zh|en`）显示中文或英文；所有动态内容都做 HTML 转义，页面没有任何脚本，CSP 为 `default-src 'none'`、样式只允许自带样式的哈希、图片只允许 https，带 `noindex`、`no-referrer`、禁止被嵌入；结果在边缘缓存 60 秒。Worker 只对 `/c/*` 和 `/invite/*` 先于静态资源运行（`assets.run_worker_first`），其他路径直接由静态资源响应；没有配置数据库地址/密钥时这两条路径照旧交给网页版 App。不碰 DNS 和自定义域名。已安装的 PWA 里，这两种路径由 Service Worker 返回应用外壳，应用按地址自己找到页面。部署：`sh tool/deploy_web.sh` 会连同 Worker 一起部署，并从 `.env` 读取 `SUPABASE_ANON_KEY` 以 `--var` 传给 Worker（不打印；anon key 本来就是公开的）。
- **Webhook**：频道 webhook（外部服务往频道发消息），公告频道转发 webhook。
- **机器人**：创建机器人账号（独立身份，不是好友），机器人 token（重置/吊销），斜杠命令注册，Bot API（见第 18 节）。

## 11. 语音、视频与通话

- **语音频道**：加入/离开、说话指示、静音/闭麦、视频、屏幕共享；人数上限；语音频道内的文字聊天；默认语音频道。
  - **频道状态**（E6）：在语音频道里的人可以写一句最多 60 个字的状态（「正在打排位」），显示在频道标题下和圈子频道列表里；空频道不显示，第一个进入空频道的人会清掉旧状态（`circle_channels.voice_status`，`set_voice_channel_status` / `list_voice_channel_statuses`）。
  - **网络质量与仅音频**（E6）：自己的头像格右上角显示 LiveKit 连接质量；网络差（差/断）持续 4 秒且有人开着视频时，房间顶部提示「切换到仅音频？」，可一键切换，也可随时用顶栏「仅音频」按钮；仅音频 = 取消订阅所有人的摄像头和屏幕共享（新开的视频也不收），自己的摄像头不受影响。
- **私聊通话 / 群通话**：一键语音或视频通话，来电提示，通话时长记录（系统消息「通话持续 1 小时 5 分钟」）。
- **舞台频道**：主持人/听众，举手、邀请上台、下台、结束舞台、编辑话题。
- **音效板（Soundboard）**：圈子上传短音效，在语音中播放给所有人。
- **语音管理**：强制静音、强制关闭声音、移动成员到其他频道、断开连接（版主）。
- **AI 降噪**：Krisp 降噪（LiveKit 插件），不可用时回退到 WebRTC 标准降噪；设置 → 语音会显示是否启用。
- **语音设置**：输入/输出设备选择、音量、成员单独音量。
- **通话链接**：生成链接（有效期可选），别人点开直接加入通话或语音频道；无权限/过期有对应页面；可撤销。
- **悬浮小窗**：离开通话页面后，应用内显示可拖动的小窗（显示正在说话的人），不会遮挡侧栏和底部面板。
- **通话表情**：通话中发送飘过的表情（有频率限制）。
- **屏幕共享放大**：观看共享屏幕时可缩放、拖动、聚焦（spotlight）。
- **背景虚化**：网页版由 WeCord 自己做（MediaPipe），iPhone/Mac 打开系统自带「人像」效果；虚化失败时摄像头保持关闭，绝不发送未虚化画面。
- **通话字幕与纪要**（E1，`lib/features/voice/captions/`）：
  - **本机识别，服务器零成本**：每个参会者的设备只识别自己的麦克风（iPhone/Mac 复用语音输入的 `SFSpeechRecognizer` 通道，网页用 Web Speech API），识别出的句子用 LiveKit 数据消息（主题 `wecord.caption`，说话人由语音服务器担保，不看消息里的自称）发到房间，所有人拼成字幕条；说话中的句子用不可靠通道、说完的句子用可靠通道。不支持的设备（Android、Windows、没有 Web Speech 的浏览器、识别被拒绝）会让别人看到「xx 的设备不支持字幕」。
  - **谁能开**：由 `livekit-token` 在签名令牌里写入参与者属性 `cap=1`（来自 `can_current_user_host_captions`，迁移 `202610240100`）：语音/舞台频道里有「静音成员」权限的人（圈主、管理员、对应角色）；一对一通话的双方；群通话的发起人和群主/管理员。别人发来的「字幕已开启」只有来自带这个属性的参与者才算数，所以不能靠发消息冒充。发起者每 20 秒重复一次、有人加入时再发一次，75 秒没听到就自动关闭，发起者离开通话也会关闭。
  - **同意**：所有人都会看到顶部「字幕已开启 · 谁开的」；每个人可以随时「不共享我的字幕」（仍能看到别人的）、在自己屏幕上隐藏字幕条、切换识别语言（中文 / English）。识别要把音频交给 Apple 服务器或浏览器厂商的语音服务时，先单独征求同意。自己的麦克风在通话里关着（静音、闭麦、没按住说话）时不识别。
  - **字幕条**：深色通话页和聊天里的通话卡片都有；最新几行 + 正在说的一行；对比度达标、字号随系统字号（条会滚动而不是截断）、最新一行定稿的字幕是读屏的 live region（说话中的行不朗读）、尊重「减少动态效果」。设置面板里有文字记录。
  - **纪要**：发起者关闭字幕（或离开通话）时可选「生成纪要」：文字记录发给 `ai` 函数的 `meeting_recap`，返回标题、要点、决定和待办；一键存成会话里的共享笔记并在聊天里发笔记卡片（`create_note_from_blocks` + `share_note`），待办可一键转成任务/活动（复用 F4 的审核面板，不会自动创建）。沿用每人每日 AI 次数、圈子/群关 AI 和个人 AI 开关；只有愿意共享字幕的人的句子会进文字记录，也只有这些会发给模型。
  - **隐私**：**不录音、不存音频**。文字记录只在设备内存里（最多 3000 行），通话结束或字幕关闭就丢掉，不写入任何数据库或文件；只有发起者生成纪要时，纪要（不是逐字稿）才被写进笔记。服务器不保存字幕、不保存逐字稿，`ai` 函数只记当天请求次数。
- **限制**：系统级画中画不支持（库不支持），只有应用内小窗。

## 12. AI 功能（OpenCode Go，可切换服务商）

- **补课总结**：聊天顶栏 ✨（手机在「更多」）总结未读或最近消息；条数随消息量变化（1–8 条），只写实际出现的内容；按界面语言输出；进群时会提示「总结未读」。
- **改写**：输入框旁 ✨，选修正拼写语法 / 更简短 / 更礼貌 / 更正式 / 翻译。
- **翻译**：长按消息「翻译」，翻成设置里选的「翻译成」语言（默认界面语言），结果走服务器缓存。
- **自动翻译**：聊天「更多」→「自动翻译此聊天」后，屏幕上看得到的别人的消息自动在气泡下显示译文（可「显示原文」），只翻屏幕上的、每批最多 20 条；设置 → AI 可选「翻译成」（6 种语言）和「不翻译」的语言。译文缓存在 `message_translations`，命中缓存不调模型、不计限额；消息编辑、撤回、过期、被 AI 守护扣下时译文自动清除；圈子关了 AI 或个人关了 AI 就不翻译（`ai` 函数的 `translate_batch` 动作）。
- **语音转文字**：语音消息旁「转文字」；iPhone/Mac 本机识别（`SFSpeechURLRecognitionRequest`），转写只存在本机；可开启「自动转写」（只在本机识别时）；网页需额外配置语音识别服务（`AI_TRANSCRIBE_*`），未配置时提示去 App 使用。
- **新成员 AI 守护**（圈子级，默认关）：
  - 管理员设定「新成员」标准（加入 1/3/7 天内，或发言少于 N 条）和处理方式（扣留待审核 / 放行但标记）；
  - 新成员的文字消息先由 AI 分类（正常 / 垃圾 / 诈骗钓鱼 / 骚扰 / 色情 / 其他）；检查期间只有本人和版主可见，不推送、不计未读、搜不到；
  - 版主审核队列（菜单带数字徽标），显示类别和理由（AI 同时生成中英文理由，按界面语言显示），可批准/删除，记入审计日志；
  - AI 不可用（未配置、限额、出错、超时）时直接放行并记为「未检查」；AutoMod 仍先生效；额度计在圈子上，不扣成员的。
  - **编辑后复查**：发送者仍是新成员时，编辑文字会让消息回到「检查中」（同样的规则、同样的唤醒、超时同样放行），通过后留在原位置，不重复推送；管理者、版主、机器人、老成员的编辑不复查。
- **AI 守护 2.0**（F7，AI 守护设置里的「另外检查」，管理者设置）：
  - **投票**：新成员（和突袭锁门期间进来的人）发的投票，问题和选项一起交给 AI，和文字消息一样先「检查中」、可被扣留；默认开。
  - **活动、笔记、任务的标题**：同一批人在圈子里建的活动（标题和说明）、频道里的笔记标题、任务清单标题、任务（标题和详情），创建或修改后由 AI 检查（同一条一分钟内改多次只算一次，同一个人十分钟内最多检查十条，防止用改标题或批量建任务烧额度）。这些不是消息，没法先藏起来，所以**不扣留**：被 AI 标记的在审核页出现独立的卡片「AI 守护标记的活动、笔记和任务」（作者、类型、AI 的类别和理由），版主点「打开」去处理，再点「关闭」；AI 的标记和版主的关闭都记入审计日志（`guard_item_flag`、`guard_item_dismiss`）；红色徽标数字包含这些卡片。默认开。
  - **图片**：默认关，圈子管理者打开「图片」后，新成员发的单张图片（JPEG/PNG/WebP/GIF，不超过 3MB，存储支持缩放时先缩到 768 像素）发给视觉模型检查（见 `docs/ai-setup.md`：`AI_VISION_ENABLED`、`AI_VISION_MODEL`），被扣留的图片在审核页直接显示出来给版主看；**服务器没开视觉、模型拒收图片、读不了图片或额度用完时，图片直接放行并记为「未检查」，数据库在函数告知「可读图片」之前根本不会扣留图片**（`ai_runtime_flags`），所以没配视觉模型绝不会让图片卡住。图片按每圈每日单独限额（`AI_VISION_DAILY_LIMIT_PER_CIRCLE`，默认 100）。图片只在那一次请求里以 base64 发给模型服务商，不落第三方存储；提示词把图片和图里的文字当不可信数据。
  - 沿用现有规则：圈子关了 AI 就都不查；额度计在圈子上；AutoMod、突袭防护照常先生效；定时任务是独立的 pg_cron `wecord-ai-guard-item-sweep`（每分钟，结束超时的检查并清理旧行），没有改 `run_later_dispatch()`。
- **反诈提示**（F7）：群和圈子里，**不是你好友**的人发来的文字，如果在要钱 / 转账 / 保证金、要验证码、中奖、带单稳赚、礼品卡付款或冒充客服说账号异常，或带一个看起来可疑的链接，消息下面出现黄色提示条「谨防诈骗：对方不是你的好友」，写明该小心什么，带「举报这条消息」（走 A1 的举报流程）和「不再提醒此人」。只用规则，在本机运行，消息不发给任何人；只提示不拦截；一个人的提示关掉后（或举报后）不再重复出现；私聊（只限好友）、文件传输助手、自己的消息、机器人和 Webhook 的消息、已被 AI 守护扣留的消息都不提示。只有一个普通链接不算（陌生人发链接太常见），要地址本身看起来可疑，或消息同时在要东西。
- **链接安全检查**（G5）：`link-preview` 函数顺带返回风险（`risk.level`：none / caution / high 和原因），只看地址：地址里 `@` 前面伪装成域名、数字 IP、外观相似字符、短链接、模仿知名站点（`paypal-login.com`、`paypal.com.xxx.top`）、可疑后缀、登录或领奖字样、下载安装包、不加密还要登录等，规则累加；短链接会跟着重定向（最多 3 次）按最终地址再算一次。预览卡片上 caution 显示「小心这个链接」，high 显示「这个链接看起来不安全」；**点开高风险链接前先出现提示页**（地址、为什么有风险、「返回」是默认、「仍然打开」，同一个主机本次使用中放行一次后不再问）；预览已加载时服务器判断的重定向结果也算。提示页上有「让 AI 检查这个链接」（只在 AI 可用时，用本人每日额度，圈子或群关了 AI 就不出现）：只把地址（去掉 `?` 之后）、页面标题和描述、规则命中的原因发给模型（`ai` 函数的 `link_check` 动作），不发聊天内容，也从不打开链接；页面文字当不可信数据。规则同时在服务器（`supabase/functions/link-preview/link_risk.ts`）和 App（`lib/features/safety/link_risk.dart`）里各一份，用同一份用例文件 `test/fixtures/link_risk_cases.json` 保持一致。没有接 Google Safe Browsing（要把链接发给第三方、商用条款也没确认），只用本地规则。
- **编辑时限**（圈子设置 →「编辑消息」）：不限 / 15 分钟 / 1 小时 / 24 小时，超时的编辑被服务器拒绝（删除不受限；私聊和群不受限）。
- **@WeCord AI 助手**（F2）：
  - 在任何聊天里写 `@WeCord AI …` 就会得到回答，所有人都看得到；也可以用输入框「+」菜单或消息菜单的「问 WeCord AI」打开提问面板。
  - **读取范围由发起人选**：只读这条消息（和它回复的那条）/ 加上最近 20 条 / 加上最近 100 条；写法是提及后面跟 `/20` 或 `/100`。模型只看到发起人自己看得到的消息，已撤回、已过期、AI 守护扣留中的都不会给它。
  - 能力：回答、总结、翻译、改写、列待办。回答是机器人账号「WeCord AI」发的一条回复，下方标「AI 生成」，长按可以举报（和普通消息一样）；列待办的回答带「转成任务」。
  - 不响应的情况：圈子关了 AI、群主关了本群的 WeCord AI（群详情里的开关）、发起人自己关了 AI 开关、发起人超出每日限额（共用 `AI_DAILY_LIMIT_PER_USER`）。发起人会在自己的消息下看到「WeCord AI 正在思考…」或没有回答的原因。
  - 机器人只是回复，不是任何群的成员；提及被 AI 守护扣留的消息，放行后才会处理；机器人和编辑后的消息不会触发；每人每分钟最多 5 次。
  - 账号第一次需要时由 `ai` 函数创建（见 `docs/ai-setup.md`）。
- **提取待办与日程**（F4）：多选消息后点「提取待办」（也在 WeCord AI 的待办回答上点「转成任务」），弹层里逐条确认、改标题、改负责人和时间、选任务还是活动，确认后才创建。负责人只能是会话成员（认不出的名字留空）；时间按你的时区解析，并用和时间令牌同一个解析器复核。
- **每日速览**（F3，设置 → AI → 每日速览）：关注最多 10 个群或圈子频道（服务器触发器强制，私聊、文件传输助手、话题不能关注），选一个送达时间；每天到了你自己时区的那个时间（用设备上报的时区，旅行时跟着走；错过超过 6 小时就等明天），数据库先数一遍你看得到的新消息——**没有新消息就不调用模型**，也不扣额度。有的话 `ai` 函数（`digest` 动作）用一次请求给每个聊天写几条要点，结果是通知页一张卡片（「速览」筛选，未读计入通知角标，点某个聊天直接打开）和一条「今日速览已就绪」推送（只写有几个聊天有新动态，不含聊天内容）。只读你自己看得到的消息：已撤回、已过期、AI 守护扣留中、阅后即焚、你拉黑的人或拉黑你的人发的、系统通知、你自己发的、助手的回复都不读；圈子关了 AI、群主关了 WeCord AI、你自己关了 AI 开关就不生成；退群后订阅自动失效，圈子频道失去查看权限或圈子被下架也读不到。一份速览算一次请求（共用 `AI_DAILY_LIMIT_PER_USER`），失败退还；卡片保留两周。聊天内容在提示词里是不可信数据。账号删除级联清除，「下载我的数据」带上速览设置（不含速览正文）。
- **AI 问答：问聊天记录，带出处**（F1 阶段 1，`lib/features/ai/ask/`，`ai` 函数的 `ask` 动作，迁移 `202610250300`；阶段 2 向量/混合检索未做）：
  - **入口**：搜索页上方「搜索 / 问 AI」切换（服务器配好 AI 且本人开着 AI 才出现）。从某个聊天或圈子进入搜索时默认只问那里；要问全部聊天得自己选「全部」（没找到时也有「在全部聊天里问」）。
  - **流程**：模型把问题改写成最多 3 组关键词（模型只看到问题，看不到聊天）→ 数据库用全文搜索索引找最多 50 条消息 → 这些消息作为不可信数据（围栏 + 数据规则）交给模型，只许据此回答并用 [1][2] 引用 → 服务器把引用编号映射回消息，编号不在列表里的丢弃，所以只能引用提问者看得到的消息；再向数据库复核一次，回答期间被撤回的消息会让整条回答作废。找不到就说找不到，不瞎猜。
  - **只读提问者看得到的消息**：不含撤回、过期、被 AI 守护扣留或审核中的、阅后即焚、系统通知、AI 助手自己的回复、拉黑（任一方向）的发送者；圈子或群主关了 AI 的聊天、本人关了 AI 都不读；自己的消息可以问。出处卡片可点，跳回原聊天的那条消息。
  - **限额**：一次提问算一次请求（每日限额与其他 AI 功能共用），失败退回；没有匹配时不再调用模型回答。回答不存储。
- **AI 开关与限额**：设置 → AI 总开关；每个圈子可单独关闭 AI；每人每日用量上限；安全检查（提示词注入防护：聊天内容作为不可信数据隔离）。
- **配置**：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`（当前 OpenCode Go，`deepseek-v4.1-flash`）；可选 `AI_DAILY_LIMIT_PER_USER`、`AI_GUARD_DAILY_LIMIT_PER_CIRCLE`、`AI_TRANSCRIBE_*`。说明见 `docs/ai-setup.md`。

## 13. 朋友圈（Moments）

- **入口**：手机首页快捷行、电脑侧栏「收藏」下方；有新动态时显示最新发帖人头像（不用红点）。
- **发布**：文字（2000 字）+ 最多 9 张图，或一个短视频（≤60 秒、≤50MB），或一个链接；可加地点。
- **谁可以看**：所有好友 / 仅自己 / 部分可见（选好友或标签）/ 不给谁看（选好友或标签）。
- **点赞与评论**：评论可回复；点赞和评论只有「同时是发帖人和评论者好友」的人才能看到（服务器强制）；自己可删自己的评论，发帖人可删任何评论。
- **隐私设置**（设置 → 隐私与安全 → 朋友圈）：不让他看我的、不看他的、允许查看的范围（全部 / 半年 / 一个月 / 三天）、朋友圈推送开关。
- **封面**：可更换封面图；好友主页（`/moments/of/:userId`）。
- **实时**：好友发帖时顶部出现「N 条新动态」，点赞评论实时更新（私有信号通道只传 ID，再按可见规则重新拉取）。
- **推送与通知**：别人赞、评论、回复你的帖子或评论时推送（新帖不推送，和微信一致）；通知页有「朋友圈」分类。
- **安全**：照片和视频按帖子可见范围控制读取权限；拉黑、删好友立即失去访问；图片缩略图 480px。

## 13b. 日常（Daily，24 小时动态）+ 密友

- **是什么**：比朋友圈更轻的照片或短视频（视频 ≤15 秒、≤20MB），24 小时后消失；朋友看到可以直接回复到私聊。朋友圈是长期的，日常是 24 小时的，两者并存；「精选」（把日常收进资料）暂不做。
- **入口**：手机首页快捷行有「日常」格（没有日常时是发布入口；有日常时显示你的头像环，点一下看、长按再发一条）；有新日常的好友头像外加**强调色环**（不用红色，和状态气泡并存，已看完的变成淡细环），点头像直接看，长按进私聊。电脑侧栏「朋友圈」一行旁显示最多 3 个有新日常的好友头像环，下面一行「日常」发布。
- **发布**：拍照 / 从相册选照片 → 照片编辑器（涂鸦、文字、马赛克、裁剪）→ 说明文字（200 字）+ 谁可以看 → 发布；视频不进编辑器。手机有「拍照」「录视频」，电脑和网页只有相册。发布用客户端生成的 id，失败重试不会发两条；每人同时最多 50 条。
- **谁可以看**：复用朋友圈观众模型——所有好友 / **密友** / 仅自己 / 部分可见 / 不给谁看（选好友或标签，标签实时读取）。「不让他看我的朋友圈」的好友也看不到你的日常；拉黑或删好友立即失效（什么都不复制）；过期后谁都看不到，作者也不行；账号被删除的人的日常看不到。**密友**是自己的一份好友名单（`story_close_friends`），在「谁可以看」里选「密友」后点「编辑密友名单」；名单只有自己能读，删好友或拉黑会自动移出，重新加好友不会自动恢复。
- **查看**：全屏、顶部分段进度条（照片 5 秒，视频播到结束）、点右侧下一条 / 点左侧上一条、长按暂停、下滑关闭、电脑上 ← → 切换、Esc 关闭；写回复时自动暂停；看完一个人接着看下一个有新日常的好友；从第一条没看过的开始。**减少动态效果**：不自动前进（点按切换）、视频等你点播放、下滑关闭不做位移动画。
- **回复**：底部回复框和 6 个快速表情。回复 = 给作者的一条私聊文字消息（`send_story_reply`，遵守仅好友私信和拉黑规则，重试同一 `client_id` 返回同一条），消息附件 `story_ref`；聊天里在气泡上方显示缩略图和「回复了你的日常」，日常结束后显示「这条日常已结束」。快速表情是对日常的一次回应（每人一个，可改可撤），不发私聊消息，作者在「谁看过」里看到。
- **谁看过**：只有作者能看（`list_story_viewers`，其他人调用被拒绝；表本身任何人都不能直接读）；列表里有表情，已被删好友 / 拉黑 / 账号已删的人不显示；自己的日常上有查看数和表情数、删除按钮。
- **存储**：私有桶 `stories`（路径 `<作者id>/<日常id>.jpg|-t.jpg|-v.mp4`，每个文件 ≤20MB）；读取权限由 `story_visible_to` 决定，只有作者能写、能删自己的文件夹。
- **过期清理**：不改 `run_later_dispatch()`，有自己的任务——pg_cron `wecord-purge-expired-stories`（每 5 分钟，SQL 删除过期的日常，触发器把文件登记进清理队列）和 `wecord-expire-story-files`（每 5 分钟调 `wake_expire_stories()`，它用 Vault 里已有的 `wecord_functions_url`、`wecord_dispatch_secret` 以 `Authorization: Bearer <DISPATCH_SECRET>` 唤醒 Edge Function `expire-stories` 删除存储文件，和 `scheduled-dispatch` 同一套；任务有 pg_cron 就总会创建，密钥在运行时检查，取不到就什么都不做；没有 pg_cron 时迁移跳过，可用任何调度器调用）。
- **实时**：私有通道 `stories:<用户id>`（只传「有变化」，不传内容），客户端收到后重新读取排行；回到前台也会刷新。
- **删除账号**：触发器（`profiles.deleted_at`）删除其日常、看过记录、表情和密友名单，文件进清理队列，`delete-account` 函数同时清空 `stories` 桶里的用户文件夹。
- **数据导出**：`export_my_stories` 导出还在展示的日常（说明、受众、查看人数、文件链接）、密友名单和自己提交的日常举报；不含「谁看过」。

## 14. 位置

- **发送位置**：聊天「+」→「位置」，地图选点（拖动、附近地点、搜索），发送带静态地图预览的位置卡片；点开看完整地图，可「在地图中打开」（Apple 地图 / Google 地图 / OSM）、复制地址。
- **共享实时位置**（私聊和群聊）：15 分钟 / 1 小时 / 8 小时；共享中的人在同一张地图上以头像显示并实时移动；聊天顶部横幅「N 人正在共享位置」。
- **隐私**：每次开启需确认；位置只通过私有实时通道发给该聊天成员，服务器不存坐标；不选「精确」时在本机模糊到约 500 米；到期、点停止、退出聊天、退出登录都会自动结束；应用关闭时暂停（不在后台定位），地图上显示「已暂停」。
- **配置**：地图瓦片、地理编码、附近地点服务都可通过 dart-define 配置（`MAP_TILE_URL` 等），默认用 OpenStreetMap 公共服务（仅适合轻量使用，见 `docs/location.md`）。

## 15. 隐私与安全

- **限时消息**：私聊和群聊可设消息自动消失时间；过期消息立刻对所有人隐藏，每分钟由 pg_cron 物理删除，附带文件由后台任务从存储删除。
- **阅后即焚**：照片/视频只能打开一次，打开后 2 分钟内有效；不能转发、不进相册和共享媒体；截屏无法阻止（界面已说明）。
- **在线状态隐私**：在线状态只对好友、同圈子成员、同群/私聊成员可见；拉黑双向隐藏；「显示在线状态」关闭或隐身时服务器强制隐藏（服务器端 presence 表 + 每个查看者的私有信号通道）。
- **私有实时通道**：正在输入、笔记光标、在线状态、实时位置、朋友圈信号全部走 private 通道 + `realtime.messages` 策略；其余 postgres_changes 订阅由表级 RLS 保护。
- **存储限制**：图片 50MB（仅图片类型）、语音 50MB、文件 50MB、头像/横幅 20MB（仅图片类型）；附件路径必须在发送者所在会话的文件夹下（防伪造路径读别人文件）。
- **安全审计**：对 10-17 / 10-18 共约 45 个迁移做了攻击者视角审计，修复 7 个问题（伪造附件路径、伪造阅后即焚、接龙泄露、从审核中/过期消息创建任务泄露文字、过期消息仍可转发搜索、过期后位置继续共享、删除内容仍可读），每个都有攻击测试；所有表都开 RLS，服务器专用函数普通用户无法调用。
- **崩溃与错误报告**（自托管）：自动记录崩溃、未处理错误、意外登出、登录令牌刷新风暴、页面跳转循环、服务器请求失败；绝不发送消息内容、文件名、邮箱、令牌；设置 → 隐私与安全可关闭；数据保留 30 天；运维用 `sh tool/errors_report.sh` 查看。
- **运营后台（K1）**：平台管理员（`app_admins`：owner / moderator / support）在设置 →「运营后台」（隐藏路由 `/admin`，只有管理员看得到）处理举报：队列按待处理/已处理和类型（用户、圈子、帖子）筛选；详情页显示举报原因、举报时保存的快照、被举报对象现状、历史举报和已采取的操作；动作有「无违规」「标为已处理」、封禁用户、删除帖子、下架圈子、封停圈子（红色只用于封禁/删除/封停，都要二次确认并必须写原因）。所有操作写入 `admin_audit_log`，在「操作日志」页查看。管理员读不到任何聊天内容，只能看举报快照。圈子有两种处置：**下架**（发现页隐藏、所有加入途径关闭，现有成员照常使用）和**封停**（谁都不能进入或读取，成员看到「此圈子已被封停」，仍可退出）。封禁用户由 Edge Function `admin` 完成（`auth.admin.updateUserById({ban_duration})` + 删除全部会话）。第一个 owner 不写进迁移，由你在 SQL 编辑器里运行一条 `insert`。
- **功能开关与最低版本（K4）**：表 `feature_flags`（key、总开关、开启比例、白名单用户、需要的版本）和 `app_config`（各平台最低版本），客户端读不到表，只能调 `get_my_flags(平台, 版本)`（登录前也能调，只回最低版本和对所有人开着的开关）。开启比例按「用户 ID + 开关名」的 md5 分桶（0 到 99，同一个人永远同一个桶，比例调高只会加人）；白名单无视比例，总开关关了对所有人关；开关可要求最低版本。客户端 `featureFlagProvider('key')` 启动时拉取并缓存（SharedPreferences，只用同一用户的开关，最低版本任何人都用），失败或超时（8 秒）用缓存或 `featureFlagDefaults`，从不卡住启动。低于最低版本显示「请更新」页（网页上是「刷新」按钮，原生是「再检查一次」）；版本比较规则在数据库和 Dart 里一致，无法解析的版本一律放行。**开关只控制显示，服务端安全规则从不依赖开关**。管理在运营后台「开关」标签（owner 可改，其他角色只读），改动写入审计日志。版本号来自编译参数 `--dart-define=APP_VERSION=x.y.z`，取自 `pubspec.yaml` 的 `version`（见下文「构建与发布」）；不传时是 0.1.0。
- **官方通知（K6）**：运营后台「通知」标签发布公告（中英两版，至少一个标题），每个人的通知页顶部出现「WeCord 团队 · 官方」卡片（不发私聊，「WeCord 团队」只是卡片上的名字，不是账号）；点开展开全文并标已读，右上角叉号关闭；撤回后立即从所有人的通知页消失；新注册的人看不到注册前发的公告，公告 30 天后不再显示。通知页多了「官方」筛选，未读数计入收件箱角标。可选**推送一次**：发布时开关，一次、不能补发，24 小时内最多一条推送；由 `scheduled-dispatch` 分批（每批 500 台设备）发出，按设备语言写标题和正文开头，遵守免打扰和免打扰时段，超过 2 小时或已撤回就丢弃。「本次更新」弹窗：应用更新后第一次打开时显示，内容随版本打包在 `lib/features/announcements/whats_new_content.dart`（中英两版），已看过的版本记在本机（读写失败都不影响使用）；第一次安装只记版本不弹。
- **用户反馈（K7）**：设置 →「反馈与帮助」：文字（最多 2000 字）加可选截图。截图先缩到 1600 像素并去掉元数据，提交前能预览，可用照片编辑器的马赛克/模糊/涂画遮住隐私，再上传到**私有**桶 `feedback-screenshots`（路径 `<user_id>/<uuid>.jpg`，每人最多 20 个文件，只有本人能写/删，本人和平台管理员能读）。自动附版本和平台，不带任何聊天内容。每人每小时最多 5 条。运营后台「反馈」标签（owner/moderator/support 都能看）按待处理/已关闭/全部查看，详情显示截图（短时效签名链接）和已有回复；回复以官方通知（只发给该用户的卡片，无推送）送达，可选回复后关闭。账号删除时反馈、回复和已读标记由 `profiles.deleted_at` 上的触发器清掉，截图由 `delete-account` 函数清掉；数据导出带上自己的反馈和收到的回复（`export_my_feedback`，截图给签名链接）。
- **产品统计（K2）**：运营后台「数据」标签（任何管理员角色可读）。**不在设备上做任何埋点**，全由服务端从已有数据聚合，只存数量：`ops_daily_metrics` 每个 UTC 日一行（活跃人数、新注册、1/7/30 天留存的人数、按类型的消息数、圈子帖子/朋友圈/日常/笔记/任务/聊天活动数、语音频道分钟数（每 15 分钟抽样一次，近似值）、AI 请求数、推送成功/失败/失效、错误报告数、存储总量与增量）。「活跃」= 当天打开过 App（已注册的会话）、被在线心跳看到或发过消息/帖子/朋友圈/日常。去重人数用 `ops_active_days`：人只以加盐哈希（`ops_user_key`，盐只在 `ops_settings` 里）出现，保留 45 天，API 读不到；留存 = 某天注册的人在 1/7/30 天后那一天是否活跃（那天过完才写，写一次）。重算某一天只会增不会减（消息可能先被删）。任务：`wecord-ops-tick`（每 15 分钟：记录活跃、抽样语音、重算今天）和 `wecord-ops-daily-close`（00:20 UTC：收尾昨天、存储快照、留存、清理旧数据）。页面：范围（7/30/90 天）、四个大数字（今日/本周/本月活跃、新注册）、活跃折线、留存表、消息柱图与类型、功能使用量、健康（推送、错误、存储）、各版本与平台的「无崩溃」比例（近 7 天）。推送函数（`push`、`scheduled-dispatch`）发完后只报三个数（`ops_record_push`）。不统计 AI token（库里只记请求数）。
- **监控与告警（K3，自建，不接第三方）**：只用自己的错误报告和 Supabase 自己的数据，数据不出 Supabase。独立 pg_cron 任务 `wecord-ops-health-check` 每 5 分钟运行 `ops_health_check()`（没有改 `run_later_dispatch()`），检查：定时任务（`wecord-later-dispatch` 在 `cron.job_run_details` 里超过 4 分钟无成功运行警告、10 分钟故障）、定时任务失败（30 分钟内同一任务失败 2 次警告、5 次故障）、边缘函数调用（pg_net 的应答表里最近 15 分钟的错误/超时比例）、推送失败率（最近一小时，失效订阅不算）、错误报告激增（对比前 24 小时的小时均值）、AI 额度（每人每天 50、每个圈子 AI 守护每天 500，可在 `ops_settings` 改）、各版本崩溃用户比例（5% 警告、10% 故障，至少 10 人）、新的错误类型。缺少 pg_cron/pg_net 时对应检查为「未知」，不报警。检查结果在 `ops_checks`，异常写入 `ops_alerts`：每个检查同时最多一条未关闭的告警；连续两次正常自动关闭；一小时内复发是同一条（静默重开）；事件类（新错误）24 小时后自动关闭。新告警送达：后台「告警」标签的列表，给每位 owner 和 moderator 的「监控 · 告警」官方卡片（通知页，公告表 `kind='ops_alert'`，一人一张，告警关闭时撤回），**故障级**再加一条推送（`claim_ops_alert_pushes`，由 `scheduled-dispatch` 发，按设备语言出中英文，每小时最多 5 条，警告级只有卡片，点开进入 `/admin`）。「告警」标签还显示每项检查的结果、检查有没有在跑（心跳超过 15 分钟没更新就警告——检查本身也跑在 cron 上，cron 全停时就是这样看出来的；没有外部心跳）、最近一天的错误分组。owner/moderator 可「我知道了」和「关闭」（写入审计日志）。
- **错误报告 2.0（K5）**：服务端分组 `group_key` = 报告类型 + 错误类型 + 调用栈里第一个 WeCord 自己的帧（`package:wecord/...`，不含行号），触发器写入，`report_client_errors` 没有改；设备在 context 里多带错误类名 `type`。`ops_error_groups` 记每组首次出现的时间和版本（保留 90 天），某组累计 ≥3 条报告而之前没见过时进入 K3 告警。发版用 `--split-debug-info=build/symbols/<版本>/<平台>`，栈只有地址（头部有 `build_id`，擦除器原样保留），`sh tool/errors_report.sh --symbolize` 取最新栈，在对应版本的符号文件里用 `flutter symbolize` 还原，并按「类型 + 第一个应用内帧」重新分组；符号文件在 `build/` 下，不提交，每个版本留一份。默认的 `sh tool/errors_report.sh` 也改为按分组显示。网页版的栈是压缩过的 JS，不能这样还原。版本健康：每个版本和平台近 7 天的活跃人数与遇到崩溃的人数（「数据」标签）。
- **消息举报（A1）**：消息菜单（长按 / 右键）里的「举报」（自己的消息、已撤回的消息和系统通知不显示）。弹层有原因单选、补充说明、「附带上下文」（默认开：同时提交前后各最多 5 条你自己看得到的消息）、「同时拉黑」开关和社区准则链接；每人每天最多 20 条新举报，同一条消息重复举报返回第一条。举报时保存快照（正文、附件元数据、发送者、时间；阅后即焚媒体只留占位，附件路径一律不存），消息之后被撤回或过期也能处理。**圈子里的举报**进本圈「审核」页的「用户举报」分组（红色计数并入审核徽标；`count_message_reviews` 把待处理举报也算进去），有 `manage_messages` 的版主可以：忽略、删除消息、禁言（1 小时 / 1 天 / 1 周）、封禁，分别复用 `recall_message`、`timeout_circle_member`、`ban_circle_member`（各自检查权限，并写入圈子审计日志，另有 `report_dismiss` / `report_resolve` 条目）。**私聊和群聊的举报**进运营后台「消息」标签（`admin_list/get/resolve_message_report`，动作：无违规、删除消息、封禁发送者后关闭；写入 `admin_audit_log`）。被举报的人看不到举报，也不会出现在任何列表和计数里（即使他自己是版主或管理员）。`snapshot`、`context` 不能通过表 API 读取，只有处理人通过函数读到；处理完 90 天后由每日的 `purge_old_client_errors()` 一并清除。运营后台看不到私聊里的图片（只有文件名等元数据）。
- **社区准则、隐私政策、服务条款与年龄声明（G10）**：三个页面 `/legal/guidelines`、`/legal/privacy`、`/legal/terms`（登录前也能打开；内容是随应用打包的 Markdown，`assets/legal/<名称>.<en|zh>.md`，中英两版，每页开头有「草稿——待所有者确认」提示，文本待所有者确认）。隐私政策写明实际数据流：Supabase、LiveKit、OpenCode Go（仅用 AI 功能时）、Gotenberg、OpenStreetMap/Nominatim、GIPHY、网页推送、客户端错误报告、数据导出和删除账号。注册页必须勾选「我已满 13 岁，并同意服务条款和社区准则」，服务器记录 `profiles.accepted_terms_at` 和 `age_confirmed_at`（服务器时间）；最低年龄是唯一的常量 `minimumAge`（`lib/features/legal/minimum_age.dart`，所有者 2026-10-18 确认 13+，不做青少年模式）。老用户每次启动在顶部看到一个不挡操作的横幅（勾选并「同意」后记录，「暂不」只在本次启动内隐藏）。设置 →「关于 WeCord」列出三份文本、应用版本和开源许可页。
- **日常举报（B1）**：看日常时菜单里的「举报」，弹层同消息举报（原因、补充说明、同时拉黑；每人每天最多 20 条），进运营后台「日常」标签（`admin_list/get/resolve_story_report`，动作：无违规、删除日常、封禁作者后关闭，写入 `admin_audit_log`）。日常 24 小时就结束，所以举报保存快照（说明文字、类型、作者、时间、文件名）；有未处理举报的日常，文件最多多保留 30 天，管理员只在举报未处理期间能读到它的文件；处理 90 天后清除快照。
- **其他**：拉黑、举报用户、举报公开圈子、两步验证、设备管理、资料可见范围、删除账号、数据导出。

## 16. 通知与推送

- **通知页**（`/notifications`）：@提及、回复、提醒、任务、活动提醒、朋友圈互动、好友请求、官方通知（K6）；按类型筛选；未读数显示在铃铛和图标上。
- **网页推送**（Web Push / VAPID）：新消息、@提及、通话、提醒、定时消息发出、任务指派与到期、活动提醒、朋友圈互动；推送文字按收件人的语言和时区；同一会话的通知可合并（tag）；推送被服务器「认领」一次，不会重复。
- **本地通知**：App 打开时的本地通知。
- **免打扰**：在线状态设为「请勿打扰」时不推送；会话/圈子静音；消息预览开关（推送是否显示内容）；测试通知按钮。
- **免打扰时段与重要联系人**（设置 → 通知 → 免打扰时段）：按设备时区设开始/结束时间（可跨午夜）和重复的星期（按「开始」的那天算）；时段内不推送，通知页照常记录。星标好友、@我、来电、指定的「重要联系人」可按开关突破（好友资料页有「重要联系人」开关）；与「请勿打扰」和会话/圈子静音叠加。服务器端在 `push`、`scheduled-dispatch`、`chat-event-reminders` 发送前过滤；设置存在 `user_notification_settings`，「消息预览」开关也搬到了这张表。时段内用户面板的铃铛显示小月亮。
- **后台调度**（pg_cron 每分钟 `run_later_dispatch()` → `scheduled-dispatch` 函数）：发出到点的定时消息（重复的发出后写下一条）、各类提醒推送、任务到期提醒、活动提醒、朋友圈推送补发、好友生日提醒（收件人当地 9 点）、官方通知的那一次推送（分批）、加急消息的第二次推送和「请确认公告」推送、清理过期文件。
- **加急消息**：见第 6 节；加急推送不受免打扰时段、静音和「请勿打扰」限制，通知页的「待确认」分类计入角标。
- **限制**：iPhone / Mac 原生推送（APNs）尚未实现，App 关闭后基本收不到通知（需要付费 Apple 开发者账号）。

## 17. 个性化与设计

- **主题**：浅色 / 深色 / 跟随系统；高对比度模式（浅/深两套）。
- **玻璃效果**开关（关闭省电，也是「减少透明」）。
- **显示密度**：舒适 / 默认 / 紧凑。
- **聊天背景**：12 款代码绘制的内置背景（每款有浅深两版，与气泡和页面颜色保持足够对比，有自动测试）或自己的照片（拖动定位、深色模式调暗、模糊）；可设全局默认或单个聊天；多设备同步，仅自己可见；高对比度/关闭玻璃时自动回到纯色。
- **聊天字号**：设置 → 外观 → 「聊天字号」滑块（小 / 默认 / 大 / 更大 / 最大，0.88×–1.5×），在系统字号之上再调，只影响聊天里的消息列表（页头、输入框不变）。
- **在线状态不只靠颜色**：头像角上的状态点带形状——在线实心、闲置新月、请勿打扰横杠、离线空心圈；读屏读出状态。
- **语言**：中文 / English，推送也跟随。
- **存储空间**：设置 → 聊天 → 「存储空间」。显示 WeCord 在这台设备上占的空间：缓存的消息、已下载的文件、预览图、识别的文字和字幕、壁纸照片、等待发送的附件（最后一项不会被清）；可按种类清、按聊天清（该聊天缓存的消息 + 已下载的文件 + 预览图）、一键全清，清之前都会提示「再打开会重新下载、用流量」；可设「自动清理 7/30/90 天没打开过的媒体」（每天最多一次，只清文件、预览图和识别文字，消息保留）；只删本机副本，不影响服务器。撤回、删除、过期的消息，对应的本机缓存（已下载文件、预览图、识别文字、转写、字幕、缓存的消息行）会跟着删。网页版只显示浏览器存储用量（`navigator.storage.estimate`）、缓存的消息、识别文字和壁纸，没有文件缓存也没有自动清理。
- **无障碍**：所有页面通过无障碍守卫测试（点击目标尺寸、标签、对比度，浅色/深色/高对比度）；读屏支持（消息作为一个节点朗读、自定义操作）；减少动画；大字号（1.6×、2.0×）布局检查；键盘可达。
- **设计系统组件**（`lib/shared/ui/`）：WeCordButton、WeCordIconButton、WeCordTextField、WeCordSegmented、WeCordSwitch、SettingsGroup/Row、PersonAvatar/ThingAvatar、WeCordGlass、玻璃菜单、底部弹层、可拖拽分隔条等；颜色通过 `WeCordTokens`（含 badgeMention/badgeUnread/live 等语义色）。
- **颜色语义**：红色只用于需要你处理的事（@提及、好友请求、审核队列、逾期任务、错误）；普通未读为灰色；「正在直播」为绿色；NEW 分隔线为强调色。

## 19. 网页版与安装（PWA）

- **可安装**：Chrome/Edge 设置里「安装 WeCord」，独立窗口运行，四个快捷入口（新消息、收藏、朋友圈、通知）；iPhone Safari 一次性提示「分享 → 添加到主屏幕」；Safari 可「添加到程序坞」。
- **启动画面**：设计语言 C 的加载页 + 进度条（跟随深浅色、减少动画），替代原来的白屏。
- **离线**：Service Worker 版本化缓存应用外壳，打开过一次后断网也能启动并查看本地聊天缓存；绝不缓存 Supabase API、存储签名链接、Edge Functions。
- **更新提示**：新版本发布后，打开的页面显示「有新版本 — 重新加载」。
- **未读角标**：安装后图标显示未读数，标签页标题显示「(3) WeCord」。
- **性能**：网页包 10.1MB → 9.0MB（代码高亮、二维码扫描按需加载），CanvasKit 自托管便于离线。
- **分享到 WeCord**（H12，Android 和 ChromeOS 的 Chrome）：安装后，其他 App 的「分享」菜单里出现 WeCord，可分享链接、文字、图片、视频、PDF、Office 文档（`manifest.json` 的 `share_target`，POST 到 `/share-target`）。`wecord_sw.js` 接住这个 POST：把标题、文字、链接和文件（最多 10 个，单个不超过聊天的 50 MB 上限）存进缓存 `wecord-share-inbox`（部署清理不会删它，新分享会覆盖没打开过的旧分享），再 303 跳到 `/#/share`。`/share` 页（`ShareTargetScreen`）显示要分享的内容，并列出单聊和群聊，**文件传输助手排第一**；点一下就发送（文字一条消息，图片发成聊天图片，其余发成文件），发完清空缓存并打开那个聊天。没登录时会先登录，再回到分享页；缓存里没有内容时显示「没有要分享的内容」。圈子频道和话题不在列表里。iPhone Safari 不支持 Web Share Target。
- **`web+wecord:` 链接**（H12）：安装后浏览器可把 `web+wecord:invite/<码>`、`call/<码>`、`u/<码>`、`g/<码>`（圈子邀请、通话链接、个人二维码、群二维码）交给 WeCord（`protocol_handlers`，落到 `/open?uri=…`）；只认这四种，其他内容一律忽略并回到首页。
- **推送更稳（Declarative Web Push）**（H12）：推送的内容同时带经典字段（`title`、`body`、`tag`、`url`，旧浏览器的 `push_sw.js` 读）和 Declarative Web Push 字段（`web_push: 8030`、`notification.navigate` 等，Safari 18.4 及以上直接显示，不唤醒脚本，iPhone 主屏 PWA 的订阅不会因为「收到推送却没显示」而被系统收回）。由 `sendWebPush` 统一加，`push`、`scheduled-dispatch`、`chat-event-reminders` 三个函数都走它；`navigate` 的网址取函数密钥 `WECORD_SITE_URL`，没设就用 `https://wecord.jokebear.fyi`。没有服务端算的未读数，所以暂不带 `app_badge`（App 打开时仍由前端设角标）。`push_sw.js` 同时改了：Safari 里即使 WeCord 窗口在前台也显示通知（Safari 要求每次推送都显示，否则收回订阅）；点击通知时窗口无法聚焦就新开窗口；浏览器替换订阅（`pushsubscriptionchange`）时用同一把钥匙重新订阅，下次打开 App 自动存回服务器。
- **Android Chrome 适配检查**（H1 阶段 0）：见第 23 节。

## 20. 性能与稳定性（已完成的优化）

- 聊天消息逐条缓存，打字、对方输入、在线状态变化、单条回应都不会重建其他消息（有回归测试）。

## 23. 已知限制 / 尚未实现

- iPhone / Mac **原生推送（APNs）**、**TestFlight 分发**、**通用链接**（点通话链接直接进 App）——都需要付费 Apple 开发者账号（99 美元/年）。
- **Mac 安装包签名公证**：同上；目前可打未签名 .dmg，别人首次打开需在「隐私与安全性」里允许。
- **Android 版**：原生 App 未构建（H1 阶段 1/2 要决定并花钱）。阶段 0（Android Chrome 网页适配）已做：已装为 PWA 时收推送、点通知跳转到对应聊天（`push_sw.js` 已加固）；网页语音输入修了 Android Chrome 的「连续识别把同一句越念越长地重复」（`joinSpeechResults`，只在 Android 用户代理上合并，其他浏览器不变）；「分享到 WeCord」和 `web+wecord:` 链接可用（见第 19 节）；文件上传用系统文件选择器、扫码用 `getUserMedia` 后置摄像头（二维码页另有「从图片识别」兜底）。**只能真机验证**：见本节末尾「真机待验证」。
- **端到端加密**：未实现。
- **系统级画中画**：通话库不支持。
- **网页版语音转文字**：需另配 `AI_TRANSCRIBE_*` 密钥。
- **通话字幕**：识别质量取决于设备和语言，中英文混说效果一般；按住说话（push to talk）的人每次按下后前几百毫秒可能漏字；字幕翻译未做；iPhone/Mac 在通话里与语音输入（说话变文字）共用一个识别通道，打字框开始语音输入时字幕会暂停。
- **地图**：默认 OSM 公共服务，用户多了需换带密钥的服务商。
- **Supabase Realtime「Allow public access」开关必须保持开启**：约 38 个 postgres_changes 订阅仍是公共通道（数据由表 RLS 保护），关闭可能导致聊天/圈子/语音/笔记实时更新失效；需先验证 private postgres_changes 再改。
- **公开笔记网页**是网页版 App 里的路由，不是服务端渲染的 HTML：搜索引擎本来就很难读到内容，「允许收录」只是不再要求不收录；不能给这类页面单独设内容安全策略（只有 `note-public` 的 JSON 带 CSP）；改域名/DNS 后链接的站点前缀以 `WECORD_SITE_URL` 为准。笔记 PDF 里的文字不可选中。评论不推送，只进通知页。AI 提取的待办是笔记里的待办块，不会自动进任务清单。
- **AI 守护**检查文字、投票（问题和选项）、活动 / 笔记 / 任务的标题，图片需圈子打开并且服务器配了视觉模型（见 AI 守护 2.0）；笔记正文、群里的活动（群聊活动不属于圈子）、已有内容不检查；活动、笔记、任务只标记不扣留；图片放行后若再编辑（改说明）不复查；放行后再编辑文字，新成员期内的会重新检查（见 AI 守护的「编辑后复查」）。
- **反诈提示和链接检查**都是提示，不是拦截：规则会有误报（正常的转账、客服话术），用户可以对某个人关掉提示、对某个主机放行；短链接的最终地址只在预览能拿到时才知道；链接规则看不出页面内容。
- **合并转发**不能发到圈子频道；接龙编号按加入顺序（有人退出会变）；朋友圈不支持多视频；导出不含笔记内图片（导出笔记为 PDF 时图片会画进去）。
- **iPad**（H4）：Xcode 工程是 iPhone + iPad（`TARGETED_DEVICE_FAMILY = "1,2"`），iPad 支持四个方向，不设 `UIRequiresFullScreen`，所以支持分屏（Split View）、Slide Over 和台前调度（Stage Manager）；窗口宽度变化时界面按宽度重新布局（≥840 电脑布局，600–840 手机布局但不紧凑，<600 紧凑手机布局），页面状态保留。做了三处 iPad 修正：① 触控板/鼠标悬停消息出现操作条（以前 iPad 因为「触屏平台」被关掉了；手指不会触发悬停，所以触屏不受影响）；② 设置里的「键盘快捷键」入口在 iPad 上显示（窗口较长边 ≥960 就算平板，分屏窄窗口也算）；③ Cmd+K / Cmd+/ / Cmd+J / Option+↑↓ 在 iPad 外接键盘上沿用 Mac 的键。截图测试：`tool/screenshots/ipad_screenshots_test.dart`（1024×1366、1366×1024、834×1194、分屏 507×1366）。
- **存储空间**：iPhone/Mac 的图片只在内存里缓存（没有磁盘图片缓存），所以「已下载的文件」只含在查看器里打开过的文件、视频和语音；清理前下载的文件按「不属于任何聊天的文件」归类（之后再打开会记下来源）；网页的 Service Worker/浏览器自己的缓存不在统计里（只在浏览器用量里体现）。
- **图片描述**：没做 AI 生成建议；新增语言界面（繁体、日、韩）需要母语者校对，没做。
- **视频字幕**：时间轴来自系统识别的词级时间，长视频要先整段下载再识别（可能要几十秒到几分钟），字幕断句是按停顿和长度粗分；真机待验证。
- **真机待验证**：视频字幕（`TranscribePlugin` 的视频/分段参数）、扫码、定位权限、语音输入/转写识别质量、通话字幕（通话中 iPhone/Mac 识别与通话共用麦克风）、图片文字识别、修图手感、PWA 安装/离线/更新提示、私有实时通道在托管 Realtime 上的行为；**Android 手机**：Android 上的返回键（弹层打开时按返回会离开当前页面，弹层随页面一起关）、键盘遮挡输入框、语音输入（Web Speech）重复文字是否消失、相机扫码、文件上传、点推送跳转、分享到 WeCord、`web+wecord:` 链接；**iPad**：分屏/台前调度拖动调整宽度、触控板悬停、外接键盘快捷键、安装到 iPad；**iPhone 主屏 PWA**（iOS 18.4+）：推送是否稳定、点通知是否打开对应聊天。
